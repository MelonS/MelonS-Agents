# YouTube 게시 규칙 (하드 룰)

채널은 실계정이다.  실수가 조회수가 아니라 **계정 신뢰도**에 남는다.

---

## 1. 교체는 "삭제 → 업로드" 순서다 (하드 룰)

이미 올린 영상을 수정본으로 바꿀 때:

```
scripts/yt-delete.py <기존 videoId>      # 먼저
scripts/yt-batch-upload.sh <메타 디렉터리>   # 그 다음
```

**절대 반대로 하지 않는다.**  수정본을 먼저 올리면 그 사이 채널에 같은
내용 2편이 존재한다.  비공개·예약 상태여도 채널에 올라간 것이다.

**왜 심각한가** (운영자 2026-07-31: "이런 문제 심각한 문제야. 계정에
안좋은 영향 미침"):

- 같은 내용 중복 게시는 **스팸 신호**로 읽힌다
- 시청자 혼란 — 어느 쪽이 진짜인지 모른다
- 알고리즘 신호가 두 영상으로 쪼개져 둘 다 죽는다
- 예약이 겹치면 같은 시각에 두 편이 동시 공개된다

**실제 사고**: 2026-07-31 리센느 ep.2.  영상 소재가 내용과 맞지 않아
수정본(`IOEgWU160wg`)을 먼저 올리고 원본(`y6_MLbss9l0`)을 나중에
지우려 했다.  둘 다 8/1 08:30 예약 상태로 공존했다.

## 2. 능력이 "없다"고 말하기 전에 실제로 호출해본다 (하드 룰)

같은 사고에서 두 번째 실수: "업로드 토큰은 `youtube.upload` 스코프라
삭제 권한이 없다"고 **확인 없이 단정**하고 운영자에게 수작업을 넘겼다.

실제 토큰 스코프:
```
youtube.upload  youtube  youtubepartner
```
`videos.delete` 는 정상 동작했다 (HTTP 204).

→ 권한·기능 부재를 선언하기 전에 **1회 실제 호출로 검증**한다.
   추측으로 운영자에게 일을 넘기지 않는다.

## 3. 업로드 전 체크

- [ ] 같은 미션의 **기존 업로드가 있는지** 확인 — `scripts/yt-delete.py --list`
- [ ] `_filename` 은 **ASCII 경로**.  한글 파일명은 업로더가 JSON 을 플랫폼
      기본 코덱으로 읽으면서 깨진다 (실측: `mp4 not found`)
- [ ] `publishAt` 은 **미래 시각**.  과거면 즉시 공개되지 않고 private 로 남아
      수동 전환이 필요하다
- [ ] 예약 시각이 **다른 편과 겹치지 않는지**
- [ ] 수익 창출 정책 확인 (현 채널은 구독자 20명 → YPP 미달, 구조적으로 비수익)

## 4. 쿼터

YouTube Data API: 10,000 units/day.  업로드 1회 = **1,600 units** → 하루 6편.
삭제는 50 units.  재업로드 실수는 쿼터도 태운다.
