- **[medium]** Precomputed skill-drift finding is a false positive — root cause is CRLF plus a parser bug, not a real job-hunt gap — `scripts/audit-skill-drift.sh:70-91`, `skills/job-hunt/config/activation.tsv`
  Evidence: running scripts/audit-skill-drift.sh reports "job-hunt:
  manifest references missing script" with an empty subject field.
  Manually walking skills/job-hunt/config/activation.tsv shows every
  declared flag-to-script pair resolves to a file that exists (all 11
  sources/*.sh and 5 scripts/*.sh targets present under
  skills/job-hunt/). Inspecting the raw bytes shows CRLF line endings
  throughout the manifest, including the two blank separator lines
  (21 and 37); `git ls-files --eol` confirms the blob is stored as pure
  LF but rendered CRLF on this checkout (i/lf w/crlf attr/text=auto)
  because .gitattributes has no explicit *.tsv rule and this machine
  has core.autocrlf=true. audit-skill-drift.sh's read loop
  (IFS=tab read -r flag path env_keys) only skips a row when flag is
  exactly empty; a CRLF blank line's lone trailing carriage-return
  character (no tab to split on) survives entirely inside the flag
  variable, fails the emptiness test, and produces a bogus "missing
  script" finding against an empty path (which resolves to the skill
  directory itself, not a file). The job-hunt manifest has zero real
  drift.
  Suggested fix: (a) harden audit-skill-drift.sh to strip a trailing
  carriage return and treat whitespace-only flag values as blank; (b)
  optionally add `skills/*/config/*.tsv text eol=lf` to .gitattributes
  so this class of checkout-dependent false positive cannot recur for
  any future skill manifest.
