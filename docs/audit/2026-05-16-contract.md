## Summary

Audited all 12 hard rules and the conventions block in `docs/operator-contract.md` against
committed code, configuration, and the working tree.  This is a second contract audit pass
for 2026-05-16, running after a prior contract audit at 16:59 KST produced a DRIFT_DETECTED
verdict and triggered working-tree fixes that were applied but never committed.  The committed
code retains two rule violations: §8 (hardcoded machine-specific path in `scripts/contact-sheet.sh`)

## Findings

- **[high]** §8 violation — hardcoded machine-specific path in committed `contact-sheet.sh` — `scripts/contact-sheet.sh:9`
  Evidence: `git show 8b54cbc:scripts/contact-sheet.sh` line 9 reads
  `: "${FFMPEG_BIN:=/Users/melons/.local/opt/ffmpeg-static/ffmpeg}"`.  This is the only
  committed version of the file (one commit: `8b54cbc`).  §8 states "never hardcode `~/...`".
  A working-tree fix replaces it with `source agents/lib/env.sh`, but that fix is uncommitted.
  Suggested fix: Commit the working-tree version of `scripts/contact-sheet.sh` (the fix
  already applied) as a standalone commit referencing §8 compliance.

- **[high]** §6 violation — working-tree fixes not committed or pushed — `git status`
  Evidence: `git status --short` shows three modified files (`M CLAUDE.md`,
  `M docs/operator-contract.md`, `M scripts/contact-sheet.sh`) and two untracked files
  (`docs/audit/2026-05-16-contract.md`, `docs/audit/CURRENT-ALERT.md`).  All five paths
  are in scope for §6's auto-commit mandate (docs/, scripts/, CLAUDE.md).  The fixes for
  prior audit findings were applied to the working tree but no commit or push followed,
  leaving the repository in an inconsistent state — the working tree is cleaner than the
  committed history, but §6 requires the commit to happen "on completion."
  Suggested fix: Commit `CLAUDE.md`, `docs/operator-contract.md`, and `scripts/contact-sheet.sh`
  as a single "fix(contract): address §6/§8/§9 findings from contract audit" commit, then
  push; then commit the audit reports in a separate commit.

- **[medium]** §9 DRIFT — committed `CLAUDE.md` omits `auditor` from subagent-exclusion list — `CLAUDE.md:18`
  Evidence: Committed `CLAUDE.md` (working-tree line 18, pre-diff) reads "Subagents
  (orchestrator, planner, resourcer, editor, qa) do **not** read `docs/goal.md`..."
  `docs/operator-contract.md §9` (canonical source) lists six agents including `auditor`.
  `auditor` was added to the contract in commit `af9857f` (2026-05-15); CLAUDE.md was not
  updated at that time.  Working-tree fix adds `auditor` to both the exclusion line and
  the subagent table, but the fix is uncommitted.
  Suggested fix: Commit the working-tree `CLAUDE.md` fix (already applied).

- **[medium]** §6 scope DRIFT — committed `docs/operator-contract.md` §6 missing `docs/` — `docs/operator-contract.md:92–94`
  Evidence: Committed version of §6 reads "Every code change (anything under `agents/`,
  `.claude/agents/`, `config/`, `scripts/`, `CLAUDE.md`, `README.md`, `.env.example`,
  `.gitignore`)" — `docs/` is absent.  `CLAUDE.md`'s summary (also committed) correctly
  includes `docs/`; the two are inconsistent.  §9 of the contract states "if the two ever
  disagree, the committed file wins" — which means the narrower §6 text technically governs,
  making `docs/` changes outside the auto-commit mandate, contrary to actual practice.
  Working-tree fix adds `docs/` and `README.ko.md` to the §6 scope list, but is uncommitted.
  Suggested fix: Commit the working-tree `docs/operator-contract.md` fix (already applied).

- **[low]** §8 tension — `agents/lib/env.sh` fallback discovery uses `/opt/homebrew/...` literals — `agents/lib/env.sh:38,50`
  Evidence: `__resolve_ffmpeg()` in `agents/lib/env.sh` lists `/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`
  and `/usr/local/opt/ffmpeg-full/bin/ffmpeg` as hardcoded fallback candidates after a
  PATH lookup fails.  §8 states "never hardcode `/opt/homebrew/...`".  The design intent
  is a graceful fallback for the macOS Homebrew keg-only scenario documented in
  `docs/known-limitations.md`; a comment explains the rationale.  The previous audit
  noted these paths in its "next audit hint."
  Suggested fix: Add an inline comment citing §8 and explaining why the exception is
  intentional (macOS keg-only discovery), so future audits can classify it as a documented
  exception rather than an unreviewed violation.

- **[low]** §5 — no formal user-confirmation marker token defined — `docs/operator-contract.md:85–89`
  Evidence: §5 requires "explicit user OK" before editing `agents/*.md` or `.claude/agents/*.md`
  but does not specify what commit-message text constitutes an "OK."  The two commits to
  `.claude/agents/*.md` (`af9857f`, `27a8c86`) carry implicit user-initiation evidence
  in their message bodies, but neither uses a standardized token (e.g., `Requested-by: user`
  trailer).  Without a defined marker, auditing §5 requires reading full commit bodies, which
  is error-prone at scale.
  Suggested fix: Add one sentence to §5 defining the marker, e.g., "Include a
  `Requested-by: user` footer in the commit message to confirm the user's OK was obtained."

- **[info]** §8 structural exception — launchd `.plist` schedulers embed hardcoded user paths — `scripts/com.melons.agents.auditor.plist:11,16,19,22,49`, `scripts/com.melons.agents.queue.plist:11,15,18,21,34`
  Evidence: Both plist files contain `/Users/melons/...` absolute paths in
  `ProgramArguments`, `WorkingDirectory`, `StandardOutPath`, `StandardErrorPath`, and
  `EnvironmentVariables`.  launchd's plist format does not support shell-variable
  substitution in these keys; hardcoded paths are structurally necessary for the scheduler
  to function.  This is a known machine-swap risk: plist files must be regenerated for a
  new machine.  The username `melons` matches the public GitHub handle (`MelonS`) and is
  not a private real name.
  Suggested fix: Add a comment block inside each plist noting "machine-specific; regenerate
  with `scripts/install-scheduler.sh` on new machine" and document the regeneration step
  in `docs/architecture.md`'s Autonomous flow section.

- **[info]** `.claude/settings.json:5` — `Read` allow entry uses double-slash prefix — `.claude/settings.json:5`
  Evidence: `"Read(//Users/melons/**)"` has a double leading slash (`//`), while
  all `Write` and `Edit` entries use the standard single slash (`/Users/melons/ai/**`).
  The double slash may be an artifact of how Claude Code serialized the permission.
  Functionally opaque from the committed file alone; worth reviewing in the UI to confirm
  the effective scope matches intent.
  Suggested fix: Verify in the Claude Code permissions UI that `//Users/melons/**` resolves
  as intended; update to single-slash form if the UI allows editing.
