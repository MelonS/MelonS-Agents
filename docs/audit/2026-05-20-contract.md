## Findings

- **[medium]** Roadmap "Now" active subgoal "Land v0.4.0" is complete but not cleared — `docs/roadmap.md:29`
  Evidence: The "Now" block (last updated 2026-05-20 ~03:00 KST) reads
  "Active subgoal: Land v0.4.0 — merge feat → main, tag, README cadence batch."
  `git tag --list "v0.4*"` returns `v0.4.0`; the tag was pushed (confirmed by
  `4f43e63` README cadence batch commit referencing "v0.4.0 cadence batch" and
  `587ad01` "v0.4.0 fresh-clone regression PASS — 2026-05-20 15:01 KST").
  No `feat/skill-job-hunt` branch exists locally or on `origin`; the feat-branch
  commits (`3d6f9e0`, `cd24bb4`, `0cb319b`, etc.) are reachable on `main`. The
  roadmap Done section (most recent entry: 2026-05-20 filter-repo branch deleted)
  contains no v0.4.0 entry. Per §9: "After work lands, append a one-line entry
  to roadmap's Done section with the commit hash and date; tick any goal subgoals
  the work cleared." Neither was done after v0.4.0 shipped.
  Suggested fix: Operator to clear the "Now" active subgoal and append a v0.4.0
  Done entry with the tag commit hash; Claude may append to Done but the "Now"
  rewrite is operator-only per the §9 maintenance contract.

- **[low]** Gate 3 description in operator-contract.md is inconsistent with pre-merge-check.sh implementation — `docs/operator-contract.md:186`
  Evidence: Line 186 reads "§5 marker compliance — every commit touching
  `agents/` or `.claude/agents/*.md` carries `Requested-by: user` in body."
  `scripts/pre-merge-check.sh:108` implements:
  `grep -qE '^(\.claude/agents/[^/]+\.md|agents/[^/]+\.md)'` — using `[^/]+`
  to restrict to direct-child `.md` files only, not the whole `agents/` subtree.
  Commit `0652092` ("fix(pre-merge-check): align §5 regex to *.md scope") fixed
  the regex and documented the intent in an inline comment, but `aa56f5f`
  ("docs(contract): close audit L4/L5/L6") did not update the table row in
  `operator-contract.md`. The script and the contract now disagree: the contract
  claims broader scope (`agents/`) than the script enforces (`agents/*.md`).
  Suggested fix: Update `docs/operator-contract.md:186` gate-3 Source cell to
  read "`.claude/agents/*.md` or `agents/*.md` (direct-child .md files only)" to
  match the current `[^/]+\.md` regex in the script.

- **[low]** `outputs/publish/` contains an untracked markdown artifact not covered by gitignore — `outputs/publish/2026-05-20-batch-upload-pack.md`
  Evidence: `git status --short` shows
  `?? outputs/publish/2026-05-20-batch-upload-pack.md` (untracked, not staged).
  The file contains upload scheduling/copy for a 5-short video batch (1307 bytes;
  Korean text). The repo-wide `.gitignore` patterns cover `*.mp4`, `*.mov`,
  `*.wav`, `*.jpg`, `*.png` etc. but not `*.md`. `outputs/publish/.gitkeep`
  documentation says only "mp4/wav/jpg outputs remain globally gitignored" —
  markdown files were not anticipated. The file is currently untracked (not
  committed), satisfying the §8 "only `.gitkeep` tracked" architecture rule.
  However, there is no gitignore guard preventing a future `git add -A` or
  `git commit -a` from accidentally committing it. The file contains no secrets
  but the directory convention per architecture is tracking-free beyond `.gitkeep`.
  Suggested fix: Add `outputs/publish/*.md` (or `outputs/publish/**`) to
  `.gitignore`, or document in `outputs/publish/.gitkeep` that markdown files
  are also excluded.
