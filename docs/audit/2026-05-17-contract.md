## Findings

- **[low, carry-forward]** §8 — Four launchd plists hardcode `/Users/melons/…`
  with inaccurate migration comment —
  `scripts/com.melons.agents.auditor.plist:15,20,23,26,53`,
  `scripts/com.melons.agents.audit-poll.plist:15,19,22,25,46`,
  `scripts/com.melons.agents.disk-watch.plist:15,19,22,25`,
  `scripts/com.melons.agents.queue.plist:15,19,22,25`
  Evidence: launchd does not expand shell variables in plist XML values;
  absolute paths are structurally required.  All four plists carry an inline
  `<!-- §8 exception: … When the repo is relocated, re-run
  scripts/install-scheduler.sh on the new machine to regenerate the LaunchAgents
  copy. -->` comment.  However, `scripts/install-scheduler.sh:59` performs a
  plain `cp "$src" "$dst"` (not a template expansion), so on a machine swap
  the hardcoded `/Users/melons/ai/…` paths remain wrong even after re-running
  the installer.  Unchanged across thirteen prior audits.
  Suggested fix: Generate plists from `*.plist.template` sources via
  `sed "s|@@REPO@@|$(pwd)|g; s|@@HOME@@|$HOME|g"` at install time inside
  `scripts/install-scheduler.sh`; commit only the `.plist.template` files; add
  rendered `*.plist` files to `.gitignore`.

- **[info, carry-forward]** §11 — Two 2026-05-16 daily reports use
  `<ISO-date>-<topic>.md` naming instead of `<ISO-date>.md` —
  `docs/daily/2026-05-16-faceless.md`, `docs/daily/2026-05-16-overnight.md`
  Evidence: §11 step 3 specifies `docs/daily/<ISO-date>.md`.  The 2026-05-17
  report correctly uses `2026-05-17.md`; the anomaly is confined to the two
  legacy 2026-05-16 files.  Both carry the required content sections.

  Suggested fix: Rename both to `2026-05-16.md` (merging content) or amend
  §11 step 3 to explicitly allow `<ISO-date>-<topic>.md` variants for
