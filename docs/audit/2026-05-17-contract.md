## Findings

- **[low, carry-forward]** §12 — LinkedIn URL encodes real-name path component —
  `site/index.html:169`
  Evidence: `site/index.html:169` contains
  `<a href="https://www.linkedin.com/in/eun-hyung-choi" ...>LinkedIn</a>`.
  The URL path component `eun-hyung-choi` encodes a real-name personal
  identifier in a public, committed file.  `Requested-by: user` is present in
  the originating commit `75b10a8`.  §12 has no formal operator-override clause
  for intentionally public identity surfaces, making this a technical
  violation even if the intent is deliberate.  Unchanged across five prior audits.
  Suggested fix: Amend `docs/operator-contract.md §12` to add an explicit
  operator-override clause for identity information on intentionally public
  surfaces, then add a `<!-- §12 operator-authorized deviation -->` comment
  beside the anchor at `site/index.html:169`.

- **[low, carry-forward]** §8 — Four launchd plists hardcode `/Users/melons/…`
  with inaccurate migration comment —
  `scripts/com.melons.agents.auditor.plist:15,20,23,26,53`,
  `scripts/com.melons.agents.audit-poll.plist:15,19,22,25,46`,
  `scripts/com.melons.agents.disk-watch.plist:15,19,22,25`,
  `scripts/com.melons.agents.queue.plist:15,19,22,25`
  Evidence: launchd does not expand shell variables in plist XML values;
  absolute paths are structurally required — all four plists carry an inline
  `<!-- §8 exception: … When the repo is relocated, re-run
  scripts/install-scheduler.sh on the new machine to regenerate the LaunchAgents
  copy. -->` comment.  However, `scripts/install-scheduler.sh` performs a plain
  `cp "$src" "$dst"` (not a template expansion), so on a machine swap the
  hardcoded `/Users/melons/` paths remain wrong even after re-running the
  installer.  Unchanged across twelve prior audits.
  Suggested fix: Generate all four plists from `*.plist.template` sources via
  `sed "s|@@REPO@@|$(pwd)|g; s|@@HOME@@|$HOME|g"` at install time inside
  `scripts/install-scheduler.sh`; commit only the `.plist.template` files; add
  the rendered `*.plist` files to `.gitignore`.
