## Findings

- **[low]** §8 — launchd `.plist` files hardcode `/Users/melons/...` absolute paths — `scripts/com.melons.agents.auditor.plist:11,16,19,22,49` and `scripts/com.melons.agents.queue.plist:11,15,18-19,34`
  Evidence: `scripts/com.melons.agents.auditor.plist` line 11: `<string>/Users/melons/ai/scripts/audit-run.sh</string>`; line 49: `/Users/melons/.local/bin:/Users/melons/.local/opt/ffmpeg-static:...`. Likewise `scripts/com.melons.agents.queue.plist` line 34 PATH string.  Both plist files expose the operator's macOS username via absolute path, and would silently break on any machine swap.  §8 prohibits hardcoding `~/...`; `/Users/melons/...` is the literal expansion.  Structural constraint: launchd requires absolute paths and does not expand shell variables — `$HOME` is not a valid launchd value.  Pre-existing finding; explicitly deferred in prior audits (2026-05-15, 2026-05-16) as a technical constraint.
  Suggested fix: Add a prominent `<!-- MACHINE-SPECIFIC: replace /Users/melons with $USER home on any clone -->` comment, or generate the plist from a template at `install-scheduler.sh` time using `sed "s|/Users/PLACEHOLDER|$HOME|g"`.

- **[info] carry-forward** §5 — no formal user-confirmation marker token defined — `docs/operator-contract.md:85–89`
  Evidence: §5 requires "explicit user OK" before editing `.claude/agents/*.md` or `agents/*.md`, but the rule text does not specify what commit-message text constitutes that OK.  The two commits touching `.claude/agents/*.md` carry implicit evidence (`af9857f`: "User requested a project-wide watchdog agent…"; `27a8c86`: init commit predates the contract), but no standardised `Requested-by: user` footer exists.  Consciously deferred since 2026-05-15 (recorded in commit `05a14a9` body as "design question, not drift").
  Suggested fix: Define the marker in §5, e.g., add "Commit message must include `Requested-by: user` to record that explicit approval was obtained."

- **[info] carry-forward** §11 — daily report naming convention drift — `docs/daily/`
  Evidence: `docs/operator-contract.md §11` step 3 specifies `docs/daily/<ISO-date>.md`.  Files present: `2026-05-14.md` and `2026-05-15.md` follow the spec; `2026-05-16-faceless.md` and `2026-05-16-overnight.md` use an `<ISO-date>-<topic>.md` suffix form not in the spec.  All four files contain required sections; only the naming deviates.  No 2026-05-17 daily report yet (active session, not yet at shutdown).
  Suggested fix: Either rename the 2026-05-16 pair to plain `2026-05-16.md` (merging or keeping the first chronologically) or update §11 step 3 to permit `<ISO-date>-<topic>.md` explicitly.

- **[info]** New git post-commit hook not yet documented in `docs/audit/README.md` or `docs/architecture.md` — `scripts/hooks/post-commit.sh`, `scripts/install-hooks.sh` (committed `785dafd`)
  Evidence: `docs/audit/README.md` "Triggering audits" section (lines 58–92) lists three invocation paths (launchd, on demand, regression test) but not the new post-commit hook.  `docs/architecture.md` "Autonomous flow" section describes the launchd jobs but does not mention L1 commit-boundary detection.  The hook itself is architecturally clean — it uses `$(git rev-parse --show-toplevel)` for the repo root, runs the audit in the background via `nohup`, and logs to `records/audit/` (gitignored).  The opt-in design (`install-hooks.sh install`, not wired to `bootstrap.sh`) appropriately respects the money firewall (§3) — fresh cloners do not receive unexpected Anthropic API spend.
  Suggested fix: Add a "Post-commit hook (L1)" subsection to `docs/audit/README.md` "Triggering audits" and a bullet to `docs/architecture.md` "Autonomous flow" step 6.
