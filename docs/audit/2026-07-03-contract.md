## Findings

- **[high]** `skills/job-hunt/scripts/status.sh` crashes on this machine — CRLF line endings in the manifest it reads — `skills/job-hunt/scripts/status.sh:55-61`, `skills/job-hunt/config/activation.tsv`
  Evidence: `bash skills/job-hunt/scripts/status.sh` exits 3 with
  `[status] malformed manifest row: ''`. `cat -A skills/job-hunt/config/activation.tsv`
  shows CRLF (`^M$`) at every line end, including the two blank
  separator lines. `git show HEAD:skills/job-hunt/config/activation.tsv | grep -cU $'\r'`
  returns `0` — the committed blob is pure LF; the CRLF is introduced at
  checkout time. `.gitattributes` has explicit `text eol=lf` rules for
  `*.sh`, `*.py`, `*.yaml`, `*.yml`, `*.json`, `*.md`, etc., but has no
  rule for `*.tsv`, so the file falls through to the default
  `* text=auto` behavior; combined with this machines `git config
  core.autocrlf` = `true`, checkout renders it CRLF. `status.sh`s read
  loop (`while IFS=$tab read -r flag path env_keys; ... [[ -z "${flag:-}"
  ]] && continue`) treats a blank lines lone trailing carriage-return
  character (no tab to split on, so it lands entirely in `$flag`) as a
  non-empty, non-comment row, fails the `-z "${path:-}"` check on the
  next line, and exits. This directly violates operator-contract Section
  8 principle 4 ("the same repo must run identically on any qualified
  machine. No hardcoded machine-specific values... All paths
  env-resolved") — the failure is not a hardcoded path, but it is a
  checkout-environment-dependent break of a documented, invocable
  operator tool, on the machine currently designated primary production
  per `docs/roadmap.md`s 2026-05-25 Done entry.
  Suggested fix: add `skills/*/config/*.tsv text eol=lf` to
  `.gitattributes` (matching the existing pattern for `*.sh`/`*.yaml`/
  etc.), and harden both `status.sh`s and `audit-skill-drift.sh`s read
  loops to strip a trailing carriage-return and treat whitespace-only
  `$flag` as blank, so future CRLF checkouts fail safe instead of
  crashing.
