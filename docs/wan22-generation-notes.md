# Wan 2.2 로컬 영상 생성 — 실전 노하우 노트

> 2026-07 실전 제작(세로 쇼츠·제품 광고류 워크로드, RTX 4070 Ti SUPER 16GB)에서
> 수십 컷을 생성·채점·재생성하며 검증한 내용. 도구: `scripts/wan-i2v.py` (5B).
> 실패 사례를 포함해 기록함 — 같은 삽질 반복 방지용.

## 1. 모델 역할 분담 (5B vs A14B)

| | **TI2V-5B** (`wan-i2v.py`) | **A14B + Lightning 4-step** |
|---|---|---|
| 샘플링 | cfg 5.0 — **네거티브가 실제로 먹힘** | cfg 1 (증류) — **네거티브 무시** |
| 강점 | 제어된 깨끗한 컷, 원본(앵커) 보존 우수 | 유체·질감·사람 동작 모션 최강 |
| 약점 | 큰 동작 표현 약함 | 손 제거 불가, 회전 시 라벨 왜곡 |
| 속도 | 97f/24fps ~6분 | 81f/16fps ~7–13분 |
| 요구 | 코어 노드만 | ComfyUI-GGUF 커스텀 노드 + LoRA |

**원칙: 기본은 5B. 동작이 꼭 필요한 컷만 A14B, 단 손/라벨 통제 포기 각오.**
- A14B는 **T2V 불가** (입력 이미지 없으면 반복 비늘 텍스처로 붕괴 — 실측). 반드시 I2V.
- A14B strength(denoise 계열)를 0.6~0.7로 낮추면 원본 보존↑·라벨 왜곡↓ (기본 1.0은 많이 다시 그림).

## 2. I2V 앵커 그라운딩 (가장 중요한 기법)

**실사 사진/프레임을 입력으로 주면 해부학·라벨·구도가 유지되고 프롬프트는 모션만 담당한다.**
- 순수 T2V/생성 이미지보다 성공률이 압도적으로 높음. 쓸만한 스틸이 있으면 무조건 I2V.
- 실사 손 앵커 + 미세모션 프롬프트 + 얕은 심도 → **손가락도 온전하게 나옴** (무조건 6손가락 아님). 이때만 `--allow-hands`.
- 영상 프레임도 앵커가 됨: 스톡/실촬 영상에서 `ffmpeg -ss <t> -frames:v 1`로 뽑은 프레임에 원하는 모션을 입히는 식.

## 3. 하이브리드 원칙 (뭘 생성하고 뭘 실사로 할까)

생성 AI가 **구조적으로 어려운** 샷 — 실사/스톡 우선:
1. 펌프/노즐에서 제형이 정확히 나오는 장면
2. 제품 라벨이 선명히 읽혀야 하는 장면 (AI가 라벨 텍스트를 다시 그리며 뭉갬)
3. 얼굴 근접, 손가락 많은 장면
4. 물리적 정합성이 중요한 조작 장면 (예: 뚜껑 닫힌 채 펌핑 같은 오류를 AI가 냄 — 채점자도 놓치기 쉬움)

생성이 **승률 높은** 샷: 유체·거품·질감 매크로, 분위기/배경 모션, 미세 카메라 무브.

**왜곡 0이 필수인데 모션이 아쉬울 때의 대안: Ken Burns** (정지 원본 + zoompan 슬로우 줌).
생성 왜곡이 원천 차단됨. 단 내부 동작은 없어 정적 — 트레이드오프를 알고 선택.

## 4. 프롬프트 노하우

- **positive는 모션 중심으로** 1~3문장: 피사체 묘사보다 "무엇이 어떻게 움직이는지".
- Wan 공식 중국어 네거티브 세트가 실제로 효과 있음 (`wan-i2v.py`에 기본 내장).
- ⚠️ 부드러운 형체(거품 등)에 "settling / melting / collapsing" 류 단어를 쓰면 **형체가 무너짐**.
  형태 유지가 중요하면 "holding its shape, subtle jiggle" + 카메라 무브 위주로.
- 표정/포즈 문제(예: 눈이 스르르 감겨 졸려 보임)는 프롬프트 스티어링("eyes wide open,
  bright awake expression") + **시드 2~3개 병렬 생성 후 선택**이 가장 싸게 먹힘.
- **추상 개념 프롬프트는 얼룩으로 붕괴한다** (2026-07-03 블랙홀 쇼츠 8컷 실측):
  "stretching stream of light", "colossal unseen sphere", "lensing distortion" 같은
  개념 서술은 3연속 실패(형체 없는 blob) — **모델이 아는 구체적 천체 장면 이름**
  (tidal disruption event, accretion disk, star field)으로 바꾸자 즉시 통과.
  T2V는 "무엇처럼 보이는지"가 아니라 "무엇인지"를 말해줘야 한다.
  같은 이유로 "bright, vivid, high contrast, filling the frame"을 명시하지 않으면
  우주류 프롬프트는 화면 대부분이 암흑으로 렌더된다 (모바일에서 아무것도 안 보임).
- **같은 시드라도 해상도/프레임수가 바뀌면 구도가 달라진다** — 시안(512·17f)에서
  고른 시드를 풀(704·97f)로 올리면 다른 그림이 나올 수 있음(실측: 노랑 나선 →
  청백 입자 링). 시안 판정은 "프롬프트 방향" 검증으로 취급하고, 풀본을 **반드시
  재채점**할 것 (이번엔 전 컷이 시안보다 좋아졌지만 반대 방향도 가능).

## 5. 검증된 파라미터 (5B 기준)

- 704×1280(9:16) · 97프레임@24fps(≈4초) · steps 30 · **cfg 5.0** · shift 8.0
- 512 근처 해상도 + 프레임/스텝 축소(17f/8steps)로 ~1분 내 **저비용 시안 뽑고 → 통과분만 풀 설정 재생성**하는 2단계가 GPU 시간을 크게 아낌.
- **콜드스타트**: ComfyUI 기동 후 첫 잡은 모델 로딩(~16GB)으로 +5분. 타임아웃 여유 필수.
- VRAM 16GB에서 5B fp16 풀가동 시 여유 ~0.5GB — 동시 작업 금지 (GPU는 한 번에 한 잡).

## 6. 품질 게이트 (재생성 판단)

컷을 만들면 프레임을 뽑아 **실제로 보고** 판정할 것 (선험적 판단 금지). 즉시 실패 조건:
라벨/텍스트 왜곡 · 손가락 오류 · 얼굴 변형 · 물리 오류(닫힌 뚜껑 펌핑 등) · 형체 붕괴.
표정·디테일 미스는 시드 리롤, 구조적 미스(피사체 자체가 안 나옴)는 앵커/프롬프트 재설계.

## 7. 채점·재생성 루프 (스펙 → 생성 → 심사 → 리트라이)

컷을 "느낌"으로 채택하지 말 것. 흐름:
1. **컷 스펙 정의**: intent(의도 장면)·caption(잠금)·must_show/must_not (형식은 `.claude/agents/cut-judge.md` 참고)
2. `scripts/wan-i2v.py`로 생성 (저비용 시안 → 통과분만 풀 설정)
3. `scripts/judge-frames.py`로 프레임 추출 → **cut-judge 에이전트**가 프레임을 실제로 보고 100점 루브릭 채점
4. REGEN이면 prompt_fix 반영해 재생성 (컷당 최대 3회) → 최고점 보존

교훈: 심사자가 물리 오류(닫힌 뚜껑 펌핑 등)를 잘 놓친다 — 루브릭에 물리 타당성을 명시적으로 넣고, 반드시 프레임을 열어 본 뒤 채점하게 할 것.

## 8. 후처리 그레이딩 함정 (2026-07-03 실측)

- **RGB 왕복 블룸 금지**: `lutrgb`+`blend=screen` 하이라이트 블룸을 yuv420p 영상에
  걸면 BT.709/601 계수 뒤섞임으로 **전체가 보라캐스트**(주황→분홍, 검정→보라).
  PNG 스틸 테스트에선 멀쩡해 보여서(그래프가 RGB로 협상됨) 더 위험 — 스틸 검증을
  믿지 말고 **영상 파이프라인 그대로** 한 클립 뽑아 확인할 것.
- 안전한 미세 그레이드는 YUV 네이티브 `eq=saturation=1.12:contrast=1.03` 선에서.
  화려함이 더 필요하면 후처리가 아니라 **프롬프트에서** 해결하라
  (multicolored/vivid/spectacular + 구체 천체명 — §4 참조).

## 9. A14B·FLF·증류 실전 판정 (2026-07-05, 구미호 제작)

- **A14B GGUF + Lightning = 모션 문제의 답.** 5B의 "고개만 까딱" 대비 진짜 뜀박질·보행·
  카메라상대 이동이 나옴 (`scripts/wan-a14b-i2v.py`, 704×1280·81f ~7분). 원속 3~4초 컷
  16개 리듬이 쇼츠 정답 — 슬로모 2배는 우주류 특수효과로만.
- **FLF는 2.1 전용모델보다 A14B 경유가 정석**: core `WanFirstLastFrameToVideo`에 A14B
  GGUF+Lightning 8스텝 → 시작·끝 스틸 모두 지정, 끝 프레임이 타깃에 실제 도달(실측).
  2.1 FLF2V 14B(전용 증류 없음, ~20분+)는 예비로만.
- **증류 업그레이드**: lightx2v `260412` rank64 쌍(Kijai) — 기존 Lightning 대비 디테일↑
  모션 자연스러움 동급 이상(실측 1건+커뮤니티 검증). 신작 기본값.
- **fp8 비결정성**: 같은 시드·프롬프트도 서버 재시작 후 팔레트/구도가 달라질 수 있음(실측:
  청백→황금 꼬리). 시드는 참고값 — **확정 스틸은 파일로 보관**이 유일한 재현 보장.
- **모델 교차 후유증**: FLF(2.1)↔A14B(2.2) 스왑 반복 시 잡이 무기한 걸리는 사례(40분 타임
  아웃) — 대형 모델 전환 배치 사이 서버 재기동 습관화. 배치 스크립트에 다운감지→재기동→
  재시도 패턴 필수.
- **LoRA 스택 주의(리서치 검증)**: 가속 LoRA가 모션·카메라 무브를 억제 — 카메라 LoRA는
  high-noise 전문가에, 강도 상단으로. 단독(비증류) 8스텝은 뭉개짐.
