# Sail — 기획서 (Game Design Document)

2026-08-12. `games/naval-sail/`(대화 중 부르는 이름: **Sail**) 첫 기획 정리.
그동안 "만들어보고 → 피드백 받고 → 고치고"를 반복하며 코드부터 앞서 나갔다 —
이 문서는 그 반대로, **뭘 만들고 있는지부터 먼저 확정**하기 위한 것이다.

| 항목 | 내용 |
|---|---|
| 장르 | 범선 시대(Age of Sail) 항해 무역 게임 — **Phase 1 방향은 무역으로 제안**(§2, 운영자 확인 필요), 탐험·전투는 Phase 2+ 후보 |
| 현재 단계 | Phase 0 — 이동 프로토타입 ("배가 바다 위에서 뜨고 움직이는가"만 검증) |
| 상태 | 배·바다·카메라 2종은 만들었으나, **실플레이에서 배가 안 움직이는 버그 발견** — 원인 진단·수정 코드는 작성, 빌드·검증·커밋은 이 문서 작성 때문에 보류 중 |
| 부르는 이름 | **Sail** (폴더명 `naval-sail`은 그대로 — 대화에서만 짧게) |

## 1. 비전 — 확정된 것

- **톤**: 묵직한 배의 관성감. 즉각 반응하는 조작을 의도적으로 배제한다.
- **아트 방향**: Kenney Pirate Kit(CC0) 저폴리 스타일 — 유료 3D 생성 API(Meshy 등)
  는 money firewall 대상이라 배제, PawnSim도 쓰는 Kenney CC0 경로를 그대로 따름.
- **참고한 것**: OpenMMO(Julian-adv, CC0 아닌 코드는 안 씀 — 개념만 참고)의
  water system — Gerstner wave 3파 합성 셰이더 접근. 부력은 OpenMMO에도
  없어서 이번에 직접 설계했다(그리고 그 설계에 버그가 있었다 — §7 참고).
- **카메라**: 2.5D(고정 부감)와 3D(자유 회전 추적) 둘 다 만들어서 **플레이해
  보고 고른다** — 지금 하나로 정하지 않는 게 설계 의도다.

## 2. 코어 루프 — 제안 (운영자 확인 필요, 그래도 근거는 명확함)

**무역을 Phase 1 방향으로 제안한다.** 이유 둘:

1. **운영자 본인이 이미 이 방향을 말한 적 있다** — `skills/game-dev-agent/README.md`
   (2026-05-26 무렵)에 적힌 장기 구상: *"a lite Age-of-Sail naval trade sim"*.
   지금 와서 지어내는 방향이 아니라, 석 달 전 스스로 남긴 메모와 일치한다.
2. **에셋이 이미 있다** — Kenney Pirate Kit(이미 다운로드해 씀) 안에
   `structure-platform-dock.fbx`/`structure-platform-dock-small.fbx`(부두),
   `crate.fbx`/`crate-bottles.fbx`/`barrel.fbx`/`bottle.fbx`/`bottle-large.fbx`
   (화물), `ship-*` 여러 크기(상선·NPC선 구분용)가 통째로 들어있다. 탐험용
   섬 조경(야자수·바위·모래)도, 전투용 대포(`cannon*.fbx`)도 같은 팩에 있어서
   **셋 다 나중에 확장 가능** — 지금 무역을 고른다고 다른 방향이 막히지 않는다.

탐험·전투는 배제가 아니라 **순서** 문제다 — §4 Phase 2+.

| 방향 | 코어 루프 | 이번 팩에서 바로 쓸 수 있는 에셋 | 이번 판단 |
|---|---|---|---|
| **무역** | 항구 간 상품 운반 → 가격차 이익 → 배 업그레이드 | 부두 2종, 화물 상자 5종, 배 8종(크기별) | **Phase 1 제안** |
| 탐험 | 미지 해역 항해 → 발견(섬·유적) → 지도 확장 | 야자수 4종, 바위 6종, 모래/잔디 패치 | Phase 2+ 후보 |
| 전투 | 함대 교전 → 나포/격침 → 함선 강화 | 대포 3종(고정·이동), 난파선 모델 | Phase 2+ 후보 |

**운영자 결정 필요한 부분**: 이 제안에 동의하는지, 아니면 다른 방향을 원하는지.

## 3. Phase 1 최소 루프 — 무역 MVP (제안)

"게임"이 아니라 **"이익이 발생하는가"** 하나만 검증하는 스코프. 전투·AI·
동적 가격·여러 상품·여러 항로는 전부 스코프 밖(Phase 2+).

- **항구 2개**, 고정 위치, 부두(`structure-platform-dock-small.fbx`) 배치.
- **상품 1종**(예: 목재) — A항구는 싸게 사고, B항구는 비싸게 판다. 고정가.
  (동적 수급 가격은 Phase 1.5 — 지금은 "왕복하면 남는다"만 확인)
- **화물칸**: 배 1척당 정수 슬롯(예: 10칸). 부두 반경 안에서 정박 판정 →
  사기/팔기 UI.
- **골드** 숫자 하나. 시작 자본 → 왕복 이익 → 증가 확인이 Done 기준.

**Done when**: 플레이어가 A→B→A를 실제로 왕복 조작해서 골드가 순증가하는
걸 화면으로 확인한다. (Phase 0의 "이동감 검증"과 같은 스타일 — 숫자·감각
하나만 딱 확인하는 최소 스코프.)

## 4. 스코프 단계

- **Phase 0 (진행 중)** — 이동 프로토타입. Done when: 배가 파도 위에서
  자연스럽게 뜨고, 방향키로 실제로 움직이고 도는 게 **실플레이로** 확인됨.
  지금 여기서 막혀 있다 — §7.
- **Phase 1 (제안, §3)** — 무역 최소 루프. 착수 전 운영자가 §2 방향에
  동의해야 함.
- **Phase 1.5** — 동적 가격(수요/공급), 상품 2~3종 확장.
- **Phase 2+** — 탐험(섬 발견·지도 확장) 또는 전투(NPC 해적선 습격) 중 하나
  추가 — 어느 쪽이 먼저인지도 Phase 1 완료 후 판단.

## 5. Phase 1 시스템 분해 (§3 무역 MVP 기준)

아직 코드 없음 — 착수하면 만들 것의 목록. PawnSim 관례대로 스크립트 단위로
쪼갠다.

| 시스템 | 스크립트(가칭) | 역할 |
|---|---|---|
| 항구 | `PortEntity` | 위치·이름·판매/구매 가격(고정값 2개) 보관 |
| 정박 판정 | `DockTrigger` | 부두 콜라이더 반경 안 + 저속 조건 → "거래 가능" 상태 |
| 화물칸 | `CargoHold` | 배에 붙는 정수 슬롯 카운터(용량 상한) |
| 경제 | `TradeEconomy` | 항구별 고정가 테이블 (Phase 1.5부터 동적) |
| 거래 UI | `TradeUI` | 정박 중에만 표시 — 사기/팔기 버튼 + 화물칸/골드 표시 |
| 자본 | `PlayerWallet` | 골드 정수 하나, 증감 이벤트 |

기존 Phase 0 산출물(`ShipController`/`ShipBuoyancy`/카메라 2종/`OceanWaveSampler`)
은 그대로 재사용 — 이동은 이미 만든 것 위에 얹는다.

## 6. 에셋 계획 — 이미 있는 것만으로 Phase 1 충분

Kenney Pirate Kit(CC0, 이미 다운로드해 사용 중) 하나로 Phase 1 전부 커버된다
— 추가 소싱·유료 API 불필요. 실제 팩 안에서 확인한 목록:

| 용도 | 팩 안 파일 | Phase |
|---|---|---|
| 플레이어 배 | `ship-pirate-medium.fbx` | 이미 사용 중(Phase 0) |
| 항구 부두 | `structure-platform-dock.fbx`, `structure-platform-dock-small.fbx` | Phase 1 |
| 화물(시각) | `crate.fbx`, `crate-bottles.fbx`, `barrel.fbx`, `bottle.fbx`, `bottle-large.fbx` | Phase 1 |
| 항구 배경 | `tower-*`(6종), `castle-*`(4종), `flag-*`(7종) | Phase 1(선택) |
| 섬 조경 | `palm-*`(4종), `rocks-*`(6종), `grass*`/`patch-*`(6종) | Phase 2+(탐험) |
| 전투 | `cannon.fbx`, `cannon-ball.fbx`, `cannon-mobile.fbx`, `ship-wreck.fbx` | Phase 2+(전투) |
| NPC/상선 배 | `ship-large/medium/small.fbx`, `boat-row-large/small.fbx` | Phase 1.5+(다른 배 등장 시) |

## 7. 지금 막힌 것 — 실플레이 버그

운영자 리포트: **"배가 움직이질 않아"**. 원인 진단 완료:

`ShipBuoyancy`가 `Rigidbody.MovePosition()`을 매 FixedUpdate마다 불렀는데,
그 대상 좌표의 X/Z가 **항상 "이번 스텝 시작 시점 위치"와 같았다** — 즉 매
프레임 "이번 스텝 끝의 수평 위치는 시작 위치와 같아야 한다"고 물리 솔버에
명령한 꼴이었다. `ShipController`가 `AddForce`로 미는 힘과 정면으로 충돌해서
배가 실질적으로 거의 안 움직였다. 자동조종(`-autopilot`) 검증 때는 작은 박스
placeholder라 우연히 덜 티가 났고, Kenney 배 모델(훨씬 크고 무거운 콜라이더)
로 바꾼 뒤 실플레이에서 확실히 드러났다 — **처음부터 실키보드 검증을
안 했다는 게 근본 원인**이다(자동조종은 물리 로직만 확인했지, 진짜 조작
경로는 사람이 눌러봐야 확인된다고 스스로도 여러 번 적어놓고 실제로는
확인을 미뤄왔다).

**고친 방식** (코드 작성 완료, 빌드·검증·커밋은 보류): `MovePosition` 대신
잠긴 깊이에 비례한 위쪽 힘(`AddForceAtPosition`)을 4점에 각각 준다 — 여러
힘이 물리 솔버에서 자연히 합산되니 전진력과 안 부딪힌다. 무게중심도 콜라이더
전체 중앙(돛대 높이의 절반 — 배 위가 무거운 셈이 됨)에서 선체 하단 쪽으로
낮췄다.

**다음 세션에서 할 일**: 빌드 → 자동조종 물리 검증(로그) → 그리고 **이번엔
반드시** 실제 exe 실행해서 WASD로 확인.

## 8. 알려진 시각적 허술함 (운영자 "허술한데" 피드백)

- 하늘·수평선 사이 회갈색 띠 — 스카이박스 미설정, 기본 배경색이 샘
- 항적(wake) 없음 — 배가 움직여도 물살이 안 남
- 소리 없음
- 조작법 화면 표시 없음 (요청받음 — 코드는 작성, 아래 §9 참고)

이 항목들은 **§7 이동 버그를 먼저 고친 뒤** 순서대로 처리한다 — 안 움직이는
배를 예쁘게 꾸미는 건 순서가 아니다.

## 9. 이번 세션에서 만들었지만 아직 씬에 안 얹은 것

- `ControlsHintUI.cs` — 화면 좌하단 조작법 상시 표시(OnGUI, 프로토타입
  단계라 Canvas/TMP 없이 가볍게). 씬에 아직 안 붙임.

## 10. 검증 체계 (기존 확립)

Unity batchmode(`-executeMethod`)로 씬 생성 → 빌드 → `AutoScreenshotter`
(`-screenshot -delay`)로 스크린샷 → `Player.log` 실제로 읽고 확인. 물리
로직은 `-autopilot`(키 입력 없이 값 주입)으로 1차 확인 가능하지만, **이건
로직 검증이지 실키보드 검증이 아니다** — §7에서 이 구분을 건너뛴 게 버그를
못 잡은 원인이었다. 앞으로는 로직 확인 후 반드시 사람이 실제 exe를 눌러보는
단계를 마지막에 둔다.

## 11. 열린 질문 — 운영자 결정 필요한 것 모음 (줄어든 버전)

1. **§2 코어 루프 방향(무역 제안)에 동의하는지** — 동의 안 하면 나머지
   §3·§5·§6도 다시 짜야 한다.
2. **최종 카메라**: 2.5D / 3D / 상황별 전환 유지 / 플레이해보고 나중에.
   (1차 추천은 2.5D — 항구·주변 지형을 한눈에 보기엔 부감이 유리하다. 3D는
   몰입용 보조 모드로 유지.)
3. **상업화 여부**: 지금은 프로토타입 판단용, Steam 출시 등 실제 계획이면
   장기적으로 라이선스·스코프 판단이 달라짐(§1 CC0 선택 근거). 어느 쪽이든
   Phase 1 착수 자체는 막지 않음 — CC0라 나중에 방향 바뀌어도 다시 걷어낼
   에셋이 없다.

~~3D 배 모델 확장 경로~~ — **해결됨**: §6에서 확인했듯 Kenney 팩 하나로
Phase 1(+ Phase 2 상당수)이 커버된다. 추가 소싱·유료 API 판단은 그 이후로
미뤄도 된다.
