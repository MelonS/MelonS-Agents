## 2. 이 대회가 실제로 찾는 것 — 특색의 근거

### 대회의 테제 (공식 사이트 대회 소개 첫 문장)

> **"AI를 활용하는 사람은 많습니다.
> 우리가 찾는 사람은 AI의 다음 단계를 설계할 디렉터입니다."**

이 한 문장이 심사 기준의 요약이다.  **"AI를 썼다"는 감점 없는 기본값이지 가점이
아니다.**  대회는 그 범주를 명시적으로 기각하고 "디렉터"를 찾는다고 선언했다.

### 뒷받침하는 증거

| 출처 | 내용 |
|---|---|
| 본선 산출물 | 게임 프로토타입 + **에이전트 설계서** + **디렉팅 명세서** |
| 김상호 NHN 게임사업부문 대표 | "AI를 활용해 새로운 경험을 제안하고 이를 **실제 결과물로 구현**해볼 수 있는" 인재 / "단순히 AI 도입에 그치지 않고 **실질적인 성과**" |
| NHN 사내 동향 | 3월 'AI 스프린톤'(임직원 대상), 7/2 '2026 에이전틱 데이'(NHN클라우드·두레이 합동) — 사내에 에이전틱 워크플로를 밀고 있다 |
| 사전과제 주제 | "AI를 활용한 게임 제작" |

### 여기서 나오는 구조적 해석

본선은 **주제를 모른 채 48시간**이다.  즉 사전과제 심사는
"이 게임이 재미있나"가 아니라 —

> **"이 사람이 주제를 모르는 48시간 동안 에이전트를 지휘해 결과물을 낼 수 있나"**

의 스크리닝이다.  그리고 본선 산출물 목록(에이전트 설계서·디렉팅 명세서)이
그 답을 대놓고 알려준다.  **사전과제의 ④ AI 활용 기술 문서를 "에이전트 설계서 +
디렉팅 명세서"의 예고편 형태로 쓰면**, 심사자 입장에서 "본선에서도 되겠다"는
판단 근거가 된다.

## 3. 제안하는 특색 — **매체와 방법의 일치**

### 한 줄

> **직접 조종하지 않는 게임을, 직접 코딩하지 않고 만들었다.**

### 왜 이게 이 대회의 특색인가

PawnSim 은 이미 **간접 조작 콜로니 심**이다.  플레이어는 유닛을 직접 조종하지
않는다 — **일감을 지정**하면 콜로니스트가 각자의 **작업 우선순위·스킬·현재
니즈**로 무엇을 언제 할지 스스로 판단한다.

그리고 이 게임은 **같은 방식으로 만들어졌다.**  운영자는 터미널을 만지지 않는다
— 방향을 주면 기획·아트·구현·QA·감사 에이전트가 각자의 역할과 정책으로 스스로
판단해 만든다.

**게임의 코어 루프가 곧 대회가 찾는 역량의 은유다.**
"AI의 다음 단계를 설계할 디렉터" — 이 게임은 *디렉터가 되는 경험* 그 자체다.

이건 vibe coding 으로 게임 하나 뽑은 팀이 사후에 흉내낼 수 없다.  게임 장르
선택 자체에 박혀 있어야 성립하는 이야기이기 때문이다.

### 실행 — ④ 문서를 2층 동형 구조로

같은 다이어그램·같은 어휘로 두 층을 나란히 기술한다:

```
[1층] 게임 안 — 콜로니스트 에이전트
  · 작업 우선순위 그리드 (3인 × 9직종 × 0~4단계) = 정책 테이블
  · PawnUtilityAI = 8개 워커의 효용 집계 → 행동 선택
  · 니즈/무드/스케줄이 선택에 개입
  · 플레이어는 "무엇을"만 지정, "누가 언제 어떻게"는 에이전트가 결정

[2층] 게임 밖 — 제작 에이전트
  · 역할 분리: planner / artist / programmer / qa / ta / auditor
  · 정책: config/policies.yaml (자율 범위·머니 파이어월·로직 변경 승인)
  · 운영자는 "무엇을"만 지정, "누가 언제 어떻게"는 에이전트가 결정
```

두 층이 **같은 문장으로 기술된다**는 것이 이 제출물의 논점이다.

### 증거 (주장이 아니라 물증)

| 증거 | 무엇을 증명하나 |
|---|---|
| 공개 커밋 이력 | 언제 무엇이 왜 바뀌었는지 — 요강이 요구하는 "커밋 기록 유지"와 동일물 |
| 재현 시나리오 17종 | 버그를 말이 아니라 **재현 가능한 시나리오**로 고정 |
| TA 게이트 | 아트 자산을 **스크린샷을 실제로 보고** 채점 — 생성만 하는 게 아니라 검수한다 |
| `check-art-tone.py` | 톤 일관성을 **수치로** 판정 (팩 서명 실측 → 임계 → 자가검증) |
| 인시던트 문서 | GUID 소실·tofu·PPU 등 실패를 원인까지 기록 |
| `docs/autonomous-decisions.md` | 에이전트가 단독으로 내린 결정의 감사 로그 |

### 오늘(07-29) 세션 자체가 최고의 사례

문서에 그대로 쓸 수 있는, 날짜와 수치가 붙은 실제 사건 두 건:

1. **게이트가 사람 눈을 이겼다.**  LoRA 로 뽑은 침엽수 3시드가 컨택트시트에서는
   "괜찮아 보였는데", 톤 게이트가 휘도 0.051~0.058 로 팩 최저(0.096)보다 어둡다고
   FAIL 시켰다.  프롬프트를 고쳐 재생성해 0.144 로 통과.  게이트가 없었으면
   그대로 반입됐다.
2. **실측이 눈에 안 보이는 버그를 잡았다.**  "맵을 축소하면 나무가 없다"는 운영자
   관찰 → 씬에서 나무 좌표를 전수 추출 → x -16~18 / y -18~18 (맵은 -45~45),
   **중심거리 30~45 구간에 0그루**.  원인은 `SceneSetup.cs` 의 지역 상수
   `const int MAP_HALF = 20;` 이 정본 `TerrainLayout.MAP_HALF(=45)` 를 가리고
   있던 것.  맵이 두 번 커지는 동안 이 값만 안 따라왔다.

이건 "AI가 코드를 짰다"가 아니라 **"AI가 스스로 검증하고 자기 실수를 잡았다"**
의 물증이다.  대회의 테제와 정확히 같은 층위의 이야기다.

## 4. 실재하는 리스크 2건

### ① ElevenLabs BGM — 게임 배포는 별도 라이선스 대상 ⚠️

`ATTRIBUTIONS.md` 에 이미 경고가 적혀 있다:

> ElevenLabs Music API 생성물은 일반 콘텐츠 상업 이용은 허용되지만,
> **광고·TV·영화·게임·기업 배포는 별도 라이선스** 대상
> (`elevenlabs.io/eleven-music-v1-terms`).  이 프로젝트는 게임이므로 해당된다.

그런데 현재 상태는:
- 게임이 **공개 URL 로 배포 중** (GitHub Pages)
- 제출물 ①이 **공개 플레이 링크**, 소스도 **공개 저장소 권장**
- 요강: "타인의 저작물을 무단 도용한 경우 **모든 책임은 제출자 본인**"

"프로토타입 심사 제출"이 약관의 허용 범위인지는 **해석의 여지가 있고, 그 리스크를
지는 쪽은 제출자**다.  선택지:

| 안 | 내용 | 비용 |
|---|---|---|
| A | 절차 생성 BGM 으로 교체 (`_gen_sfx.py` 의 `bgm_ambient_sound()` 백업 경로 존재) | 음악 품질 하락, 반나절 |
| B | ElevenLabs 게임 라이선스 확보 | **유료 — 머니 파이어월, 운영자 승인 필요** |
| C | CC0/자체 제작 트랙으로 교체 | 탐색 시간 |
| D | 현행 유지 + ④ 문서에 사용 범위 명시 | 리스크 잔존 |

→ **운영자 판단 필요.**  개인적으로는 A 또는 C 를 권한다 — 상금 3.5억 규모
대회에서 라이선스 흠결로 탈락 사유를 만들 이유가 없다.

### ② Tiny Swords 재배포 금지 vs 요강의 소스 공개 요구

팩 라이선스는 **재배포 금지**인데 요강은 "전체 소스를 동일 저장소에 포함 +
공개 저장소 권장"이다.  현재 대응:

- `ts_*.png` 는 git 미추적, 재현은 `extract-tinyswords.py` (팩은 itch 에서 직접 다운로드)
- **클린 클론 폴백 경로 완비 확인** — 팩이 없어도 절차 지형 16조각
  (`tile64_grass_p00~p33`) + `flora64_*` 5종으로 정상 빌드된다.
  (오늘 `flora64_pine` 을 LoRA 로 재생성한 이유가 이 폴백 화면의 톤 때문이다.)

→ 이건 **약점이 아니라 강점으로 쓸 수 있다.**  "라이선스를 지키면서 재현
가능성을 유지하는 설계"는 ④ 문서에 넣을 만한 엔지니어링 판단이다.  다만
저장소 README 에 심사자용 안내 한 줄은 필요하다.
