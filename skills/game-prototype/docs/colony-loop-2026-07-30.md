# 콜로니가 스스로 돌지 않던 문제 (2026-07-30)

운영자 평가: 제출 영상 **100점 만점에 2점**. "이게 뭐하는 게임인지 전혀 파악이 안 됨",
"게임인지 아닌지도 모르겠어", "너무나도 미완성인데 왜 자꾸 제출물만 만들려고 하냐고".

영상이 나쁜 이유는 촬영이 아니었다 — **찍을 사건이 존재하지 않았다.**
50초 동안 아무것도 안 지어지고 0초와 50초의 맵이 같았다.  그래서 이 문서는
영상이 아니라 게임을 다룬다.

---

## 1. 증거 — 심사자 3분 시뮬레이션

`repro-scenarios/_judge-3min.json`.  심사자가 처음 3분에 실제로 하는 일(시작 →
배속 → 나무 하나 지정 → 지켜보기)을 그대로 하고 각 단계를 남긴다.

| 시각 | 식량 | 목재 | 석재 | 가치 |
|---|---|---|---|---|
| 봄 1일 10:33 | 60 | 333 | 0 | 428 |
| 봄 2일 03:56 | 54 | 333 | 0 | 428 |
| 봄 2일 18:42 | 54 | 333 | 0 | 428 |

**2 게임일 동안 한 자리도 안 움직였다.**  소비만 있고 생산이 없다.
그리고 봄 2일 저녁 `민지 정신붕괴!` 가 떴다.

## 2. 원인 A — 기분이 구멍 난 양동이였다

`PawnNeeds.mood` 는 **0 을 향해** 상시 감소하고(`moodDecay` 0.048/게임초),
`PawnThoughts` 는 감정 합계의 **델타만 일회성으로** 얹고 있었다.  두 시스템이
따로 돌았다 — 그래서 화면의 감정 내역과 실제 수치가 서로 다른 값을 가리켰다
(패널: `기본 50 + 옷 7 + 모닥불 2 + 배부름 3 = 62`, 표시: `82%`).

산수가 그대로 붕괴를 예측한다:

```
감소   0.048/게임초 × 하루 ~1000초        = 하루 −48
유입   식사 +20 × 2~3회                  = 하루 +20~30
                                    순  = 하루 −20~28
80 에서 시작 → 2일차에 임계 20 아래 → 정신붕괴
```

관측과 일치했다.  그리고 코드에는 이미 이런 주석이 남아 있었다:

> "침대 없는 콜로니는 mood 가 35 를 영영 못 넘어 영구 붕괴(마지막 1게임일
> 콜로니 전체 노동 정지)였다"

증상만 '카타르시스 복귀'로 막아 두고 원인은 그대로였다.

### 고침 — 0 이 아니라 `기본 + Σ감정` 으로 수렴

레퍼런스 콜로니심의 모델이다.  감소율·일회성 보너스·붕괴 임계 등 기존 튜닝은
전부 살아 있고 의미만 바뀐다.

- 목표보다 높으면 (식사 직후) 목표까지 내려온다 = 기존 감소와 동일
- 목표보다 낮으면 (붕괴 직후) 목표까지 **올라온다** = 회복이 가능해진다
- 목표 자체가 낮으면 (굶주림·부상·야외) 그 값에 머문다 = 붕괴는 여전히 발생한다

**게이트가 1차 구현을 잡아냈다.**  처음엔 기존 감소율을 그대로 이동 속도로 썼는데,
그러면 3점짜리 감정 하나가 반영되는 데 60초 넘게 걸린다.
`p1-mood-negative-direct`(수면 20 → 15초 안에 mood 2.5 이상 하락)가 **0.7 하락**으로
FAIL 했다.  감정이 붙었는데 기분이 안 변하면 플레이어에겐 고장으로 읽힌다 →
간극 비례(지수) 접근, 시상수 ~4 게임초로 교체.

## 3. 원인 B — 상시 작업이 0이었다

시작 상태는 `prebuiltBase = false` (#229 맨땅 시작)로 벽·바닥·화덕·연구대·농장이
전부 비활성이었다.  **침대는 애초에 목록에 없었다.**  남는 것은 저장구역뿐이다.

그래서 초기 목재 300 을 창고로 나르고 나면 **할 일이 0** 이 된다.
나무를 지정하면 그것만 베고 다시 정지한다.

이건 알려진 문제였다.  튜토리얼 코드 주석에 그대로 적혀 있다:

> "초기 목재 300 이 창고로 들어간 뒤에는 새 일감이 없어 콜로니가 정지하는데"

그리고 과거 가상 유저 평가는 이렇게 적었다:

> "게임이 자기 자신에 대해 거짓말"

문구만 정직하게 고치고 원인은 놔둔 것이다.

### 고침 — '완성된 기지'가 아니라 **자립 루프의 최소 종자**

맨땅 시작(#229)은 유지한다.  벽·창고·확장은 여전히 플레이어 몫이다.
대신 루프가 돌기 시작하는 데 필요한 최소한만 놓는다.

| 요소 | 만들어지는 상시 작업 |
|---|---|
| 침대 3 | 수면 회복(RestMul)과 기상 감정(+5).  기분 목표의 유일한 공급원 |
| 화덕 | 식량 ≥3 이면 자동 요리 → 식사 생산이 계속 돈다 |
| 경작지 6칸 | **자동 수확 + 재성장** — 영구 반복 작업 |
| 연구대 | "작업대 필요"로 막혀 있던 연구가 진행된다 |

배치 주의: `GameManager.spawnPositions` 와 모닥불을 피해야 한다.  1차 배치는 침대
하나가 콜로니스트 스폰 지점 `(-0.5,-1.5)` 과 정확히 겹쳤다.

## 4. 그리고 이번엔 경제가 폭주했다

시작 캠프를 넣고 **플레이어 입력 0** 으로 3일을 돌렸더니 식량이 **1,002** 까지 갔다
(3인 소비량은 하루 ~27).

원인: `CropEntity.growthPerSecond = 0.011` 은 **~91 게임초마다 한 번 익는다**.
게임 하루가 ~1000 게임초이므로 한 칸이 **하루 11번** 수확된다.

세계가 멈춰 있던 것을 고쳤더니 이번엔 반대로 무너진 것이다.
→ `0.0008` (≈1250 게임초 ≈ 1.25 게임일).  6칸 × 14 ÷ 1250 × 1000 ≈ 하루 67,
소비 27 대비 약 2.5배 여유.  농사가 콜로니를 먹여 살리되 방치만으로 부자가 되지는 않는다.

## 5. 결과 — 플레이어 입력 0, 3일

`repro-scenarios/_judge-loop.json` (입력을 일부러 하나도 넣지 않는다)

| | 시작 | 1일 | 2일 | 3일 |
|---|---|---|---|---|
| 식량 | 0 | 48 | 62 | 73 |
| 식사 | 0 | 15 | 15 | 15 (상한 = 3인 × 5끼) |
| 목재 | 0 (+300 바닥) | 300 | 300 | 300 |
| 정신붕괴 | — | 0 | 0 | 0 |

수확 → 운반 → 요리 → 취침이 **지시 없이 돈다.**  화면에는 침대에서 자고, 화덕에서
요리하고, 연구대에서 연구하고, 밭에서 수확하는 콜로니스트가 보인다.

이제서야 "일감을 지정하면 그들이 스스로 판단한다"는 주장이 화면에서 성립한다.

## 6. 침대를 넣자 드러난 것들 — 게이트가 잡은 5건

시작 캠프를 넣은 뒤 전체 게이트가 **5/18 FAIL** 이 됐다.  전부 "이전에는 침대가
없어서 보이지 않던 문제"였다.  침대가 없으면 수면 관련 코드가 전부 실패 경로로
빠져 증상이 숨는다 — **결손이 다른 결손을 가리고 있었다.**

### 6-1. 전원이 게임 시작 직후 자러 갔다 (가장 큰 것)

`p1-chop-selected-only` 3종이 동시에 FAIL.  프로브가 "'벌목' 미관측"만 말해서
원인을 알 수 없었다 → 프로브가 **실제 관측된 활동을 함께 보고**하도록 고쳤더니
한 줄로 답이 나왔다:

```
선택 림 '지훈' 의 '벌목' 미관측 in 12.0s — 실제 관측 활동: 취침 이동/떠도는중
```

`PawnSchedule` 기본 일정이 `h <= 6` 을 수면으로 잡는데 **게임은 6:00 AM 에 시작한다.**
즉 개시 순간 전원이 '일정상 취침'이었다.  침대가 없던 동안엔 `GoSleepAction` 이
실패해 무해했지만, 침대가 생기자 실제로 실행되면서 **플레이어의 직접 명령(우클릭
벌목)까지 밀어냈다.**  → `h < 6` (23:00~05:59 수면, 6시 기상 = 게임 시작 시각).

> 교훈: 실패 메시지는 **기대**만 말하면 안 된다.  기대와 **실제**를 나란히 놓아야
> 실패가 스스로를 설명한다.  이 한 줄이 없었으면 추측으로 몇 바퀴를 돌았을 것이다.

### 6-2. 시작 구조물이 플레이어의 첫 작업 공간을 침범했다

`p0-basics-4axis` 의 '경작 6칸 지정'이 **5칸**만 등록되며 FAIL.
침대 하나가 셀 `(-2,-3)` 에 있었고, 그 자리는 플레이어가 처음 경작지를 그리는
3×2 블록(x −2..0, y −3..−2)과 겹친다.  테스트만의 문제가 아니다 — **실제 플레이어도
같은 자리에서 막힌다.**  → 침대를 `(-6..-4, -2)` 로 이동.

### 6-3. 게임이 좋아진 것을 테스트가 실패로 보고했다

`p1-mood-negative` 가 `'배부름'` thought 을 기다리다 FAIL.  실제 활성 thought 은
`최고의 식사` 였다 — 화덕이 생겨 콜로니스트가 **날것 대신 요리한 음식**을 먹게 된 것.
어서션의 의도는 "먹었는가"이지 "어떤 경로로 먹었는가"가 아니므로,
`hasThought` 프로브가 `'|'` 로 대안을 받도록 확장하고
`배부름|맛있는 식사|최고의 식사` 로 넓혔다 (구분자가 없으면 기존과 완전히 동일).

> 이건 "테스트를 통과시키려고 느슨하게 한 것"과 종이 한 장 차이다.  구분 기준:
> **검사의 의도가 여전히 지켜지는가.**  같은 배치에서 `p1-mood-negative-direct`
> (수면 20 → 15초 안에 mood 2.5 이상 하락)가 통과하므로 '기분이 나빠지는' 경로는
> 여전히 감시되고 있다.  통과시키려고 지운 것이 아니라, 바뀐 사실에 맞춰 다시 쓴 것이다.

## 7. 운영자가 영상을 보며 짚은 것들 (같은 날)

**"집안에 침대랑 도구들을 만들지 않는다"**, **"집을 만드는게 사람의 플레이와는 완전 다름"**,
**"집안에 풀이 있고 나무가 있고 그러네"**

1·2차 시작 캠프는 침대 3개와 화덕을 **들판에 흩어** 놓았다.  사람은 방을 먼저 만들고
그 **안에** 가구를 넣는다.  가구가 허허벌판에 떠 있으면 그 자체가 "이 게임은 사람처럼
안 논다"는 신호다.  → 벽·바닥으로 방(6×5, 오른쪽 벽에 문간)을 만들고 침대·화덕·연구대를
그 안에 넣었다.  지붕은 빌더 노동으로만 승격되므로(타이머 자동 승격 폐기됨) 씬 베이크로는
못 만든다 — 플레이어의 첫 과제로 남긴다.

그리고 집을 세우기만 하고 **그 자리의 기존 오브젝트를 안 치웠다**.  집 안에 풀·나무·덤불이
그대로 남았다.  두 번 고쳤다:

| 시도 | 방법 | 결과 |
|---|---|---|
| 1차 | 이름 접두어("Grass"/"Scatter"/"Bush"…)로 제거 | **덤불 2개 잔존** — 이름 규약이 제각각이라 열거로는 못 덮는다 |
| 2차 | **위치**로 제거 (집터 안 · Starter* 아님 · 콜로니스트 아님) | 덤불 1개 잔존 |
| 3차 | 같은 정리를 **생성 파이프라인 끝**으로 이동 | 해결 (최종 패스에서 6개 추가 제거) |

3차의 원인이 핵심이다 — **스캐터·소품이 시작 캠프보다 뒤에 생성**되므로, 캠프를 만들 때
치우면 그 뒤에 다시 놓인다.  "치운 시점 이후에 누가 또 놓는다"는 순서 의존이라
정리는 파이프라인의 **끝**에 있어야 한다.

### 7-1. 건축 시 장애물 자동 정리

**"건물을 지을때 바위나 나무가 있으면 그걸 자동제거하거나 절차상 제거하는 기능이
있어야 하는데 그게 없음"**

이전 동작:
- **광맥** → 배치 자체를 거부.  플레이어가 채광 지정 → 대기 → 다시 건축을 손으로 해야 했다.
- **나무** → 배치는 되지만 완성 순간 **자재 없이 조용히 사라졌다**.  사람이라면 베어서
  목재를 얻는다.

이제 청사진을 놓는 순간 그 칸의 나무·광맥에 **벌목·채광이 자동 지정**된다.
콜로니스트가 치우고, 자재가 정상적으로 들어오고, 건설은 그 뒤에 이어진다.
회귀 가드로 `p5-build-autoclear.json` 을 추가했다 (나무 위·광맥 위 각각 검사).

> 범위는 운영자가 지목한 나무·바위로 한정했다.  열매덤불은 작고 피하기 쉬워 점유로
> 남겼다 — 범위를 넓힐수록 회귀 위험이 커진다.

### 7-2. 타이틀 — 정지 화면에서 살아 있는 디오라마로

**"타이틀에 애니메이션이 있어야해 머라도 움직여야"** →
**"줌만 하지말고 레이어를 나눠서 돌린다던지 먼가 화려해야"** →
**"밤낮이 바뀌고 사람이 왓다갓다 하고 머가 생겼다가 없어지고 그정도는 되야지"**

측정부터 했다.  두 프레임의 차이가 **평균 0.02/255 · 변화 픽셀 0.0%** — 기능은 있었지만
주기 16초 · 진폭 ±22px 이라 사실상 정지 화면이었다.

`MainMenuDiorama` 를 신설해 **게임이 이미 가진 것**으로 타이틀에서 핵심 루프를 보여준다:

| 요소 | 구현 | 운영자 요구 |
|---|---|---|
| 밤낮 순환 | 24초 루프 색조(새벽→낮→노을→밤) | "밤낮이 바뀌고" |
| 걸어다니는 콜로니스트 4인 | **실제 보행 시트**(`pawn32_v*`) 사용, 깊이별 크기·속도 | "사람이 왓다갓다" |
| 별·창불 | 밤에만 페이드인, 개별 반짝임 | "머가 생겼다가 없어지고" |

측정 결과: **평균 0.02 → 16.9~23.1, 변화 픽셀 0% → 73~82%**.

배경도 실사풍 AI 이미지에서 **픽셀아트 키아트**로 교체했다 — 게임이 픽셀아트인데
타이틀만 실사풍이면 그 자체가 톤 붕괴다 (운영자의 일관된 원칙).

**두 번 틀렸고 둘 다 실측이 잡았다:**
- **캐릭터가 거꾸로 걸었다** (운영자 지적).  PingPong 의 진행 방향을 부호 조합으로
  역산했는데 왕복 구간에서 뒤집혔다.  → 역산하지 말고 **두 시점의 실제 위치 차분**으로
  방향을 정한다.  정의상 틀릴 수 없고 왕복 지점에서도 자동으로 맞는다.
- **화면 좌측·하단에 검은 띠**.  이동 폭을 ±46px 로 올렸는데 최소 배율 1.005 로는
  오버스캔이 모자랐다.  필요 배율 = 1 + 2×46/1920 ≈ 1.048 → 기준 배율 1.16(최소 1.075).
  테두리 어두운 비율로 검사해 3프레임 모두 0% 확인.
