# 아트 패스 — 밸류 위계 복원 (2026-07-29)

**계기**: 운영자 "그래픽 폴리싱은 필요하다고 느낌.. 아직 별로인 게임같아보여서 말이야"

**한 줄**: 화면에서 제일 밝은 것이 게임플레이상 의미 없는 *지면*이었고, 캐릭터가
제일 어두웠다.  콜로니심의 밸류 위계가 통째로 뒤집혀 있었다.

---

## 1. 진단 — 느낌이 아니라 실측

상대휘도 L (WCAG relative luminance, 알파>20 픽셀 평균):

| 요소 | L | 비고 |
|---|---|---|
| 모래 지형 | **0.737** | 화면 최고 밝기 |
| 잔디 지형 | 0.400 | |
| 물 | 0.242 | |
| 나무 | 0.108 ~ 0.167 | |
| **콜로니스트** | **0.095 ~ 0.220** | 화면 최저 |

폰(L 0.105)과 나무(L 0.108)가 **같은 밴드**다.  콜로니심에서 내 사람과 배경
오브젝트가 같은 밝기면 5초 안에 캐릭터를 못 찾는다.  야간 페르소나 QA 다수가
독립적으로 같은 지적을 했다 (11세 "개미만해요" / 캐주얼 "검은 점 세 개" /
스트리머 "개미집 구경인데 개미가 안 보임").

### 결정적 계산

잔디(L 0.400) 위에서 캐릭터가 3:1 로 뜨려면 **L ≥ 1.30** 이 필요하다 — 물리적으로
불가능(최대 1.0).  즉 **"폰을 밝게"만으로는 절대 안 풀린다.**  지면을 낮춰
캐릭터가 올라설 밸류 헤드룸을 만드는 것이 유일한 해법.

이 계산이 이 패스의 방향을 결정했다.  실측 없이 "캐릭터를 밝게 하자"로 갔으면
시간만 쓰고 안 됐을 것이다.

선형광에서 gain 을 곱하고 채도만 소폭(0.92) 조정.  **색상각(hue)은 한 도도
건드리지 않아** 팩의 색 아이덴티티는 유지된다.

### (d) 수종 5종 — TS 스타일 LoRA 정합 생성 + **톤 게이트 신설**

> 운영자 지침 (2026-07-29): "아트의 톤유지가 중요하다.  특정 오브젝트의 퀄리티가
> 좋더라도 톤이 다르다면 게임 전체의 완성도가 낮아 보인다."

#### 문제 — 5종 슬롯에 같은 스프라이트가 다섯 번

```csharp
// 전 (아트 B2)
SpeciesSprites = new[] { tsTree, tsTree, tsTree, tsTree, tsTree };
```

게임 로직은 이미 5종 분포(Pine30/Birch20/Oak20/Maple15/Spruce15)를 굴리는데
화면엔 전부 같은 나무가 나와, 45그루 맵이 단일 수종 모노컬처로 읽혔다.
B2 주석은 이걸 "종별 실루엣은 정합 생성 후속"으로 **미뤄둔** 것이지 거부가 아니다.

#### 1차 시도와 그 실패 — 기존 flora64 배선

이미 커밋돼 있던 `flora64_*`(FLUX 소지, 2026-07-24 `8fad8bb`)를 배선했다.
다양성은 생겼지만 **팩과 톤이 어긋났다** — 특히 자작 L 0.476 으로 잔디(0.280)보다
밝고 콜로니스트 리넨(0.600) 바로 아래라, 방금 복원한 밸류 위계를 나무가 침범했다.
원 커밋 자신이 "알려진 중간 상태: 밀도 혼재 — 단계 교체 예정"이라 적어둔 미완이었다.

#### 정본 경로 — `scripts/gen-trees-lora.py`

확정 아트 노선(RESUME-2026-07-24 §1 "뒤집지 말 것") = **유기물은 TS 스타일 LoRA
정합 생성**.  나무는 유기물이므로 이게 원래 정답이었다.
`tswords_v1.safetensors` + 트리거 `"tswords style game sprite, a ..."`.

#### 톤을 눈이 아니라 수치로 — `scripts/check-art-tone.py`

톤 판정을 사람 눈에 맡기면 재현이 안 된다.  스프라이트를 하나씩 확대해 보면
"잘 나왔다"고 판정하는데, 인게임에서 무너지는 건 개별 품질이 아니라 팩과의
**통계적 서명 불일치**다.  팩 12종(ts_tree/sheep/wood_pile/gold_pile/deco_01~08)을
실측하니 서명이 놀랍도록 일관됐다:

| 축 | 팩 범위 | 무엇을 잡나 |
|---|---|---|
| **외곽 휘도(하위5% L)** | **0.009 ~ 0.012** | 어두운 웜 아웃라인.  12종이 사실상 동일 — 가장 강한 서명 |
| **색 수(8단계 양자화)** | **4 ~ 9** | 플랫 셀셰이딩 |
| 평균 채도 | 0.33 ~ 0.60 | |
| 평균 상대휘도 | 0.10 ~ 0.41 | 캐릭터 밸류 대역 침범 방지 |

임계가 옳은지는 **팩 자신이 전부 PASS 하는지**로 검증한다 (`--self-test` → 12/12 PASS).
게이트가 자기 기준선을 통과 못 하면 임계가 틀린 것이다.

#### 게이트가 실제로 잡은 것

**① 색 수 405~1022 (팩 4~9).**  512px 생성물을 ~96px 로 LANCZOS 축소하면 중간색이
수백 종 생기고 1px 아웃라인이 평균에 먹혀 흐려진다(외곽 휘도 0.012 → 0.065).
확대해 보면 잘 나왔는데 **팩과 다른 종류의 이미지**가 돼 있었다 — 운영자 지적의
정확한 사례.

복구는 3단이고 **순서가 고정**이다:

```
채도 정렬(pull_saturation) → 팔레트 양자화(quantize) → 팩 아웃라인 확정(ensure_outline)
```

아웃라인을 양자화보다 먼저 넣으면 median-cut 이 그 색을 이웃 어두운 색과 합쳐
서명이 흐려진다.  팩 아웃라인색은 실측 `(22, 28, 46)` — ts_tree·ts_deco_07 의
최빈 최암부가 정확히 이 값이고 ts_sheep 도 (22,23,38) 로 사실상 같다.

**② 내 눈이 놓친 것.**  침엽 3시드가 컨택트시트에선 괜찮아 보였는데 휘도
0.051~0.058 로 팩 최저(0.096)보다 어두웠다.  프롬프트의 `dark green` 이 원인 →
`sunlit green` 으로 고쳐 재생성, 0.144 로 통과.  **게이트가 없었으면 그대로 반입됐다.**

#### 키잉 — 배경색 선택이 곧 알고리즘 제약

FLUX 는 알파를 못 내므로 평면 배경에 그린 뒤 키잉한다.  1차 배경 마젠타(H340)는
단풍 빨강(H10)과 30° 밖에 안 떨어져, 잔상 제거 임계를 조금만 올려도 단풍 잎이
같이 파였다 — 실측 **tol60에서 8.6%, tol80에서 27.6% 손실**.  패치 대신 원인을
없앴다: 배경을 **청보라(H262)** 로 교체(가장 가까운 청록과도 82° 여유) + 키잉은
반드시 **모서리 시드 flood fill**(연결성 기반).  단순 색거리 임계는 쓰지 않는다.

| birch | s1001 | 0.012 | 10 | 55.4 | 0.301 |

종별 틴트(±12%)는 그대로 두었다 — "실루엣이 정체성, 틴트는 은은한 보조"라는

## 4. 방법론 — 왜 이번엔 안 틀렸나

1. **생성기가 커밋본을 재현하는지 먼저 확인했다.**  `_gen_pawn32.py` 를 임시 폴더에
   돌려 커밋된 8장과 **비트 단위 동일** 확인.  이게 아니었으면 팔레트를 바꿔도
   diff 에 남의 변경이 섞여 뭐가 내 탓인지 몰랐다.
2. **수치로 목표를 잡고 이분탐색으로 gain 을 맞췄다.**  "좀 어둡게" 가 아니라
   "L 0.400 → 0.280" 이고 결과가 0.280 으로 나왔다.
3. **매 판단을 합성 이미지로 눈으로 확인했다.**  머스터드 위장은 숫자로는 안 보이고
   (L 은 충분히 떴다) 모래 위에 올려놓고서야 보였다.
4. **실루엣 불변을 검증했다.**  알파 마스크가 전 변형에서 동일 — 레이아웃/앵커 회귀 0.
