## 근본 원인

`ts_*.png.meta` 가 `.gitignore` 대상이었다. Unity 의 `.meta` 는 에셋의 **GUID** 를 담고,
씬·타일 에셋은 스프라이트를 GUID 로 참조한다. 메타를 커밋하지 않으면:

- 체크아웃마다 Unity 가 `ts_*.png` 를 새로 임포트하며 **새 GUID** 를 발급한다.
- 따라서 브랜치마다 같은 그림에 서로 다른 GUID 가 붙는다.
- 병합하면 한쪽 GUID 가 채택되는데, 그 GUID 는 상대 체크아웃에 **존재하지 않는다**.

`a06df81` ("Unity 에셋 포맷 정렬", langgraph-migration 브랜치 → main 병합분) 이 정확히
그 일을 했다. ts_* 참조 **14건**이 유령 GUID 로 덮였다:

| 대상 | 깨진 참조 |
|---|---|
| `Assets/Tiles/{Grass,Dirt,Water}.asset` | 지형 3종 (grass·sand·water) |
| `Assets/Scenes/Game.unity` | 나무, 폰 4종(blue·purple·red·yellow), 양, 목재더미, 고기더미 |

## 왜 게이트가 못 잡았나 (이게 진짜 교훈)

- `repro_all.py` / `webgl_smoke.py` 는 **행동·부팅·콘솔에러**를 본다. 스프라이트가
  누락되면 Unity 는 조용히 아무것도 그리지 않는다 — 예외도, 콘솔 에러도 없다.
- `webgl_smoke.py` 의 화면 어서션은 "콘트라스트 극값 차 ≥30" 뿐이다. UI 와 나무 몇 그루로
  이 조건은 통과한다. **지형이 통째로 빠져도 PASS 다.**
- `design-qa.md` 5단계는 *새 아트 반입*에만 걸린다. 이미 반입된 아트가 **참조 해제로
  사라지는** 경로는 어떤 게이트도 감시하지 않았다.

## 조치

1. **참조 복원** — `Game.unity` + `Tiles/*.asset` 을 `a06df81^`(688acd0) 으로 복원.
   위치 대응 기반 GUID 치환을 먼저 시도했으나 그 커밋이 씬 블록 **순서까지 재배열**해
   대응 가정이 깨졌다(충돌 779건) — 그래서 파일 복원으로 전환. `a06df81` 이후
   `Game.unity` 를 건드린 커밋이 없어 안전했다.
2. **`.gitignore` 수정** — `ts_*.png` 만 미추적, `ts_*.png.meta` 는 **커밋**한다.
   메타는 임포트 설정 + GUID 텍스트이지 아트 데이터가 아니므로 팩의 재배포 금지
   조항과 무관하다. 이게 이 사고 계열의 근본 차단이다.
3. **`.gitattributes`** — `*.unityweb`/`*.wasm`/`*.data` 를 명시적 `binary` 로.
   `site/play/` 로 WebGL 빌드를 커밋하기 시작했으므로 줄바꿈 정규화가 wasm 을 손상시킬
   여지를 없앤다.
