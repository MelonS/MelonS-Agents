# QA 를 실제 유저에 가깝게 — 방법 리서치 (2026-07-29)

**운영자**: "QA를 최대한 실제 유저와 비슷하게 진행할 방법들 좀 리서치해줘. 이거 너무 중요한데."

---

## 0. 결론 먼저

**LLM 페르소나는 실제 유저의 대체재가 아니다.**  이건 취향 문제가 아니라 측정된
사실이고, 우리 프로젝트에서도 이미 같은 실패가 났다.  그러므로 페르소나를 **판정자**로
쓰면 안 되고 **가설 생성기**로만 써야 한다.  판정은 계측과 게이트가 한다.

그리고 우리에게는 유리한 조건이 하나 있다 — **예측해야 할 유저가 "일반 유저"가 아니라
"10분짜리 심사자" 한 종류로 좁혀져 있다.**  좁은 표적은 계측하기 쉽다.

---

## 1. 근거 — LLM 시뮬레이션 유저의 한계는 측정돼 있다

### ICLR 2026, *Lost in Simulation: LLM-Simulated Users are Unreliable Proxies
for Human Users in Agentic Evaluations* ([arXiv 2601.17087](https://arxiv.org/abs/2601.17087))

미국·인도·케냐·나이지리아 실제 참가자와 LLM 시뮬레이션 유저를 같은 과제로 대조한 연구.

| 발견 | 내용 |
|---|---|
| 견고성 없음 | 시뮬레이션에 쓴 LLM 을 바꾸면 에이전트 성공률이 **최대 9%p** 요동 |
| 체계적 오정렬 | **어려운 과제는 과소평가, 중간 난이도는 과대평가** |
| 집단별 편향 | AAVE·인도 영어 화자에서 가장 부정확 — 프록시 정확도가 집단마다 다름 |

### *What Would GPT Click* ([arXiv 2605.18302](https://arxiv.org/pdf/2605.18302))

합성 참가자의 관찰된 실패 양상: **암묵적 피드백 부재**, **과장된 긍정·친절**,
**환각**, **문자 그대로 해석해 화용론을 놓침**.

### 우리 프로젝트에서 실제로 난 같은 실패

2026-07-27 야간 페르소나 QA 라운드에서 **프로듀서 페르소나가 "건축 서브메뉴가 깨졌다"고
보고**했다.  실제로는 멀쩡했고, 원인은 내 캡처 스크립트의 낡은 좌표였다.
페르소나는 게임을 본 게 아니라 **내가 준 잘못된 화면을 보고 그럴듯한 결론을 지어냈다.**
위 논문의 "환각 + 과장" 항목 그대로다.

또 하나: 1라운드 페르소나들은 전부 "느낌"만 냈다.  2라운드에서 **실측 도구를 쓰라고
명시**하고서야 숫자가 나왔고, 그 숫자들(WCAG 대비 45곳 중 3곳 통과 등)이 실제 수정으로
이어졌다.  즉 유용했던 것은 페르소나의 판단이 아니라 **페르소나가 수행한 측정**이었다.

## 2. 그래서 어떻게 하나 — 4층 구조

아래로 갈수록 신뢰도가 높고, 위로 갈수록 싸고 빠르다.  **판정 권한은 아래층에만 준다.**

```
4층  페르소나            가설 생성 전용.  "여기가 이상할 것 같다" 까지만.
3층  측정 게이트          지각적 주장을 수치로 판정 (톤·대비·색수·PPU·폰트)
2층  행동 계측(퍼널)      의견이 아니라 행동 기록.  어디서 막히는가
1층  실제 사람 1~3명      최종 근거.  어떤 자동화도 대체 못 한다
```

### 4층 — 페르소나는 가설 생성기로만

규칙 세 개면 충분하다.

1. **화면을 실제로 보게 한다.**  게임 설명이 아니라 방금 뽑은 스크린샷·로그를 준다.
   보지 않고 쓴 보고는 소설이다 (위 프로듀서 사례).
2. **결론 금지, 관찰만.**  "무엇이 보였는가 / 무엇을 하려 했는가 / 무엇이 막았는가".
   원인 추정과 수정 제안은 받되 **판정으로 취급하지 않는다.**
3. **모든 지적은 재현 시나리오나 측정으로 바꾼 뒤에만 고친다.**
   재현이 안 되면 그건 버그가 아니라 가설이다.

> 이 규칙은 이미 이 레포의 교훈으로 기록돼 있다 — "오딧 단일 소스로 기능 삭제 결정
> 금지, 컷 전 코드 레벨 재검증 의무" (`systems-inventory-2026-07-24.md`).
> 같은 원칙을 QA 전반으로 확장하는 것뿐이다.

### 3층 — 지각을 수치로 (이미 하고 있는 것)

"톤이 이상하다"는 재현이 안 되지만 "외곽선 휘도 0.028 vs 팩 0.012"는 재현된다.
현재 가동 중인 것: `check-art-tone` · `check-asset-refs` · `check-sprite-ppu` ·
`check-font-coverage` · `spec-sync`.

**핵심은 임계의 타당성을 스스로 검증하게 만드는 것** — 각 게이트의 `--self-test` 가
기준선(팩 원본, 알려진 사고 재현)을 통과/검출하는지 확인한다.  오늘만 해도 톤 게이트의
채도 하한이 **돌·광맥을 전부 오탐**했고 자가검증이 그걸 드러냈다.

### 2층 — 행동 계측: 의견이 아니라 "어디서 막혔나"

실제 플레이테스트가 실제로 건지는 것은 소감이 아니라 **행동**이다.
업계 표준 진행법도 같은 말을 한다 — 설명하지 말고, 끼어들지 말고, 관찰하고 기록하라
([Level Design Book](https://book.leveldesignbook.com/process/blockout/playtesting),
[indieop](https://www.indieop.com/blog/how-to-run-your-first-indie-game-playtest-and-actually-get-useful-feedback)).

우리가 자동으로 뽑을 수 있는 행동 지표 = **첫 세션 퍼널**:

| 마일스톤 | 왜 보나 |
|---|---|
| 게임 시작 → 첫 일감 지정까지 시간 | 튜토리얼 ① 이 읽히는가 |
| 첫 청사진 배치까지 | 건축 진입 장벽 |
| 첫 구조물 완공까지 | 자재 운반 루프가 도는가 |
| 첫 식사 조리까지 | 생존 루프가 도는가 |
| 10분 시점 정착지 가치 | 그 시간에 뭐가 만들어지는가 |

이 값들은 **의견이 아니므로 LLM 편향의 영향을 받지 않는다.**  여러 세션을 돌려
분포를 보면 "어디서 막히는가"가 나온다.

> 한계는 정직하게 적어 둔다: 우리 재현 시나리오는 **스크립트**라 버튼을 항상 찾는다.
> 실제 유저는 못 찾을 수 있다.  퍼널 계측은 "지정하면 그다음이 도는가"는 답하지만
> **"지정할 줄 아는가"는 답하지 못한다.**  그건 1층에서만 답이 나온다.

### 1층 — 실제 사람 1~3명 (대체 불가)

문헌이 일관되게 말하는 것: **소수의 실제 유저가 임의 수의 시뮬레이션을 이긴다.**
진행법은 단순하다.

- 사전에 **설명하지 않는다.**  설명이 필요하면 그게 곧 발견이다.
- 10분 타이머, 생각을 소리 내어 말하게 한다(think-aloud).
- 막혀도 **끼어들지 않는다.**  완전히 멈췄을 때만 개입하고, 그 지점을 기록한다.
- 끝나고 묻는다: "이 게임은 뭘 하는 게임이었나요?" — 5분 안에 읽혔는지의 최종 판정.

## 3. 우리 경우의 특수 조건 — 유저가 "심사자"로 좁혀져 있다

일반 게임 QA 는 유저 분포를 모르는 채 싸운다.  우리는 다르다.

- 심사 대상은 **NAN 2026 사전과제 심사자**
- 접점은 **링크 클릭 → 브라우저 → 첫 10분**
- 심사자는 우리 게임을 **설명 없이** 연다
- 판단 근거는 요강이 명시한 것들: 실행되는가 / 뭘 하는 게임인지 읽히는가 / 문서가 프로세스를 증명하는가

즉 우리가 시뮬레이션해야 할 것은 "다양한 유저"가 아니라 **"콜드 오픈 10분"** 하나다.
페르소나 20명보다 이 한 퍼널을 정확히 계측하는 쪽이 낫다.

**권고 우선순위**
1. 콜드 오픈 10분 퍼널 계측을 붙이고 반복 실행 → 분포 확보 (2층)
2. 운영자 본인 + 지인 1~2명에게 **설명 없이** 10분 (1층).  D-12 에 가장 싸고 가장 강한 근거
3. 페르소나는 계속 쓰되 **가설 생성 전용**으로 강등 (4층)

## 4. 하지 말 것

| 하지 말 것 | 이유 |
|---|---|
| 페르소나 수를 늘려 신뢰도를 얻으려는 것 | 편향이 상관돼 있어 20명이 1명보다 낫지 않다.  논문의 오정렬은 표본 수로 안 사라진다 |
| 페르소나 보고를 근거로 기능 삭제·대공사 | 이미 한 번 당했다 (있지도 않은 버그) |
| "느낌" 항목을 게이트에 넣는 것 | 재현 불가 → 게이트가 흔들린다 |
| 게이트 임계를 검증 없이 신뢰 | 오늘 톤 게이트가 돌·광맥을 전부 오탐했다.  `--self-test` 없으면 몰랐다 |
