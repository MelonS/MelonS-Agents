# 제출 소개 영상 — 어떻게 찍는가

**정본 산출물**: `art-out/demo/pawnsim_demo_2026-08-09.mp4` (59.1초 · 1920×1080 · 30fps)
**재현 명령**: 아래 [3줄](#재현)

> 이 문서는 "어떤 영상이 좋은가"가 아니라 **어떤 함정이 있었는가**를 남긴다.
> 좋은 영상론은 다시 쓸 수 있지만, 여기 적힌 함정들은 전부 실제로 밟아 봐야
> 알 수 있었던 것들이고 다음 사람이 똑같이 밟게 되어 있다.

---

## 왜 다시 찍었나

2026-08-08 운영자 평가: *"지금 영상 머하는 게임인지도 모르겠고 쓰레기 영상 같음"*.
방향 지시는 세 마디였다 — *"게임을 소개해야지"*, *"사람의 관점에서 생각하라고"*,
*"마을 전체"*.

기존 영상을 실측해 보니 실패 이유가 셋이었다.

| 문제 | 실측 |
|---|---|
| 너무 멀다 | `ortho ≈ 14` — 주민 머리 위 **활동 라벨이 안 읽힌다**.  게임이 이미 화면에 그리고 있는 "누가 지금 무엇을 하는가"가 해상도 아래로 사라졌다 |
| UI 가 시청자용이 아니다 | 화면의 **15%** (하단 버튼 5.1% + 튜토리얼 2.1% + 초상화 1.4% …).  튜토리얼 문구는 **조작하는 사람**을 위한 것이다 |
| 사건이 없다 | 55초가 사실상 1샷.  약탈자·늑대·폭풍이 게임에 다 있는데 영상엔 하나도 없었다 |

배율 실측: `14`=점 / `10`=겨우 / **`7`=또렷** / `5`=크지만 화면이 좁다.

## 무엇을 찍는가 — 마을의 하루

아침에 일하러 흩어지고, 밥을 짓고, 벽을 올리고, 밤에 불을 켜고, 손님(약탈자)을
맞고, 다시 아침을 맞는다.  콜로니 심을 좋아하는 사람이 하는 말은 늘 *"내 콜로니에
이런 일이 있었는데"*다 — 지표가 아니라 **사건과 사람**이다.

자막 5줄.  화면이 이미 말하는 것을 반복하지 않는다.

```
조선 산골. 여섯 사람이 마을을 이뤘다.
일감만 정해두면, 누가 무엇을 할지는 주민이 정한다.
밥을 짓고, 나무를 베고, 벽을 올린다.
밤이 오면 등에 불을 켠다.
그리고, 손님이 온다.
당신은 방향만 정한다. / 마을은 스스로 살아간다.
```

## 요강 준수

> "실제 게임 플레이 장면을 중심으로 … AI 를 이용한 조작·합성이나 타인 영상의
>  도용은 불가.  실제 플레이 화면 그대로." · **30~60초**

`TrailerDirector` 는 **게임을 실제로 플레이시키고 카메라만 옮긴다.**  화면에 없는
것을 만들어 넣지 않는다.  촬영 전 워밍업은 "게임을 더 플레이한" 것이지 합성이 아니다.
자막은 텍스트 오버레이다.

## 밟은 함정 — 전부 실측으로 드러난 것들

### 1. 녹화 경로가 게임을 **다른 상태**로 돌린다 → 빌드가 직접 프레임을 덤프

`record-gameplay.py` 는 Unity **에디터**를 배치모드로 띄운다.  같은 연출인데:

| | 빌드 | 에디터 녹화 |
|---|---|---|
| 침대 | 6개 | **3개** |
| 목재 | 1,600 | **270** |
| 목표 | 550 | **450** |
| uGUI 텍스트 | 정상 | **전부 빈 박스** |
| 화질 | 선명 | **흐림** |

제출물의 실체는 빌드다.  그래서 빌드에 `-trailerframes <dir>` 를 주고 **게임이
직접 PNG 를 덤프**한 뒤 ffmpeg 로 합친다.

- `Time.captureFramerate = 30` — Unity 가 **가상 시간**으로 돈다.  저장이 아무리
  느려도 프레임당 정확히 1/30 초가 흐르므로 결과 영상에 끊김이 없다.
- 단, `captureFramerate` 는 `Time.deltaTime` 만 고정하고 **`unscaledDeltaTime` 은
  실제 경과 시간 그대로**다.  이걸 모르고 연출을 `unscaledDeltaTime` 으로 재다가
  8.5초 컷에 프레임 35장, 게임 시간 5분짜리 영상이 나왔다.  캡처 중에는 **프레임
  수가 시간**이다 (`TrailerDirector.Dt`).
- `ScreenCapture.CaptureScreenshot` 은 저장을 다음 프레임으로 미루는데 매 프레임
  부르면 앞선 요청이 조용히 버려진다 — 1,746장 요청에 **879장**(정확히 절반).
  `CaptureScreenshotAsTexture` + `WaitForEndOfFrame` 으로 동기 저장해야 한다.

### 2. 게임 시작 직후를 찍으면 **빈 터**가 나온다 → 워밍업

자원 0 · 벽 없음 · 주민 전원 취침.  첫 촬영이 정확히 그랬다.
연출은 촬영 전에 20배속으로 게임내 23시간을 돌린다.

- 워밍업을 **실시간 46초**로 끊었더니 빌드는 2일차 3시, 에디터는 1일차 17시까지
  갔다.  프레임률이 다르면 시뮬레이션 진행도가 다르다.  → **게임 시계 목표**로 끊는다.
- 게임은 **일시정지로 부팅한다** (`GameManager.PauseAtStart`).  워밍업이 배속을
  올려도 1프레임 뒤에 0으로 덮여, 190초 상한을 다 쓰고 게임 시계가 6시→6시였다.
  프레임 순서에 따라 되기도 하고 안 되기도 하는 **경합**이라 조건으로 끊었다
  (`&& !TrailerDirector.Enabled`) + 워밍업 루프가 매 프레임 배속을 재확인한다.
- 워밍업 구간은 **검은 화면**으로 덮는다.  20배속 빨리감기를 영상에 넣을 수 없고,
  동시에 **어디서 잘라야 하는지를 영상이 스스로 알려준다**(`trim-trailer.py` 가
  `ffmpeg blackdetect` 로 찾는다).  끝에도 페이드아웃을 넣어 끝점도 같은 방식으로 찾는다.

### 3. 화면이 자막을 **반박**한다

두 번 겪었다.

- *"일감만 정해두면 누가 무엇을 할지는 주민이 정한다"* 자막 위에 주민 다섯이
  모닥불 앞에 **가만히 서 있었다.**  워밍업으로 목재가 목표(550)를 넘자
  `ColonyAutoWork` 가 자동 지정을 멈춘 것 — 규칙대로다.  → 연출이 플레이어 역할을
  해서 촬영 내내 벌목·채굴을 지정하고 오후에 증축 청사진을 놓는다(`KeepBusy`).
- *"밤이 오면 등에 불을 켜고 눕는다"* 자막 위에 **빈 이불 여섯 채.**  주민이 언제
  눕는지는 게임이 정하지 실행마다 다르다.  → 밤 컷에서 일감을 끊고(`busyPaused`),
  **자막을 화면이 반박할 수 없는 문장으로** 바꿨다("등에 불을 켠다").

### 4. 클라이맥스 컷에 **적이 없다** (세 번 실패)

| 시도 | 결과 |
|---|---|
| 습격 컷에서 소환 | 약탈자가 맵 외곽에서 걸어온다 — 컷이 끝나도 도착 전 |
| 밤 컷에서 소환 | 3배속이라 **5.2초 만에** 접근·전투·격퇴가 다 끝남.  컷 시작 때 이미 아무도 없음 |
| `EventsSuspended` 로 자연 습격만 차단 | 이야기 카드("새들의 징조")까지 사라짐 — 이 게임에서 가장 보여주고 싶은 것 중 하나 |

최종: **습격 일정만** 잠그는 `AIDirector.RaidsSuspended` 를 두고, 자막과 **동시에**
소환한 뒤 배속을 낮춘다.  자막 3초 동안 어둠 속에서 다가오는 모습이 잡히고 전투는
다음 컷에서 벌어진다.  **접근 자체가 이미 그림이다.**

곁가지 둘:
- `SpawnRaid` 는 30% 확률로 **미친 멧돼지 떼**로 갈린다.  맥락 없이 처음 보는
  사람에게 읽히지 않으므로 연출 호출은 `allowManhunter: false` 로 약탈자를 고정한다.
- 카메라가 위협 **무게중심**을 잡으면 약탈자가 흩어졌을 때 아무도 없는 빈 들판을
  본다(배율 13까지 빠져 적이 점이 됨).  **마을에 가장 가까운 위협 하나**를 잡는다.

### 5. 시계가 **뒤로 간다**

- 연출이 "오늘의 그 시각"으로 옮기면, 워밍업 종료 시각이 실행마다 달라 목표가
  현재보다 이를 때 하루가 되감겼다.  로그: `2일 9:10 → 1일 8:01`.  화면 위
  "정착 N일째"가 영상 중간에 되감기는 셈이다.  → `Hour()` 는 **다음에 오는** 그
  시각으로만 간다(단조 증가 보장).
- 밤 컷이 자정을 넘긴 뒤 "23시로" 옮기면 하루가 통째로 점프한다
  (`3일 0:07 → 3일 23:00`).  → 습격 컷은 시계를 건드리지 않고 배속만 바꾼다.
- 그 위에, **녹화 경로에서만** `GameSeconds` 가 컷 도중 시작값으로 리셋되는 것을
  관측했다(빌드 12회에서는 없음).  원인은 연출 밖으로 보이지만 증상을 먼저 막는다 —
  `LateUpdate` 가 되감김을 감지해 되돌린다.  빌드 직접 덤프로 옮긴 뒤로는 발생하지 않는다.

### 6. UI 가 **자기 배경에 묻힌다** (게임 본체 결함 2건, 고침)

- 자원 패널의 값 변화 강조가 **밝은 노랑**(1, 0.95, 0.35)이었다.  패널 배경이
  크림색이라 그 줄이 1.2초간 통째로 사라진다.  촬영 프레임 6장 중 5장에서 한 줄씩
  안 읽혔고, 매번 다른 줄이라 UI 버그로 보이지도 않았다.  → 어둡고 진한 호박색.
- 석재 칩이 "갈색 계열과 분리"하려고 **밝은 청회색**(0.70, 0.76, 0.84)이었다 —
  그 밝기는 배경과 거의 같다.  **구분은 색상이 하고 가독은 명도가 한다.**
  → 런타임에서 명도 상한(0.58)을 건다(`ResourceCounterUI.Readable`).  씬 값을
  고치면 `SceneSetup` 재실행에 되살아나므로 코드가 단일 정본이 되게 했다.

### 7. 그 밖

- 자막 흰 글씨 + 검은 아웃라인만으로는 **잔디 위에서 사라진다**.  밝기가 비슷한
  배경에서는 외곽선이 대비를 만들지 못한다 → 하단 그라디언트 스크림(단색 박스는
  '자막 바'처럼 보인다).
- 여섯이 나란히 누우면 이름표가 **한 덩어리**가 된다.  밤·습격 컷은 라벨을 내린다.
  단 `PawnNameLabel.enabled = false` 로는 **안 꺼진다** — 라벨은 자식 GameObject 의
  TextMesh 라서 컴포넌트를 멈추면 마지막 글자가 그대로 남는다.
- 벌목 지정 반경을 좁게(18) 잡았더니 60초 만에 집 둘레가 **그루터기밭**이 됐다 → 26.
- 검증 스윕은 인스턴스를 7개씩 동시에 띄운다.  운영자 피드백 *"7개가 켜지니깐 너무
  시끄러운데"* → `-mute` (Unity 스탠드얼론에는 음소거 CLI 인자가 없어 게임이 직접 받는다).

## 재현

```bash
# 1. 빌드
python skills/game-dev-agent/scripts/agent.py integrate \
  --project skills/game-prototype/unity-project --method build

# 2. 프레임 덤프 (약 4분 — 워밍업 48s + 본편 59s + PNG 저장)
"$(python skills/game-dev-agent/scripts/latest_build.py)" \
  -autostart -trailerframes "G:\\ai\\_frames" -mute \
  -logFile "G:\\ai\\_fr.log" -screen-width 1920 -screen-height 1080 -screen-fullscreen 0

# 3. 합성
ffmpeg -y -framerate 30 -i "G:/ai/_frames/f%05d.png" \
  -c:v libx264 -preset slow -crf 18 -pix_fmt yuv420p -movflags +faststart \
  skills/game-prototype/art-out/demo/pawnsim_demo_<날짜>.mp4
```

컷 타임라인은 로그로 검증한다 — 프레임을 시점 추측으로 찍어 뒤지면 한 번에 한
순간밖에 못 본다.

```
grep '\[Trailer\] t=' G:/ai/_fr.log
```

각 줄이 `컷 이름 · 게임 날짜/시각 · 약탈자 수 · 위협 유무`를 남긴다.  **시각이
단조 증가하는지**와 **추격 컷에 적이 있는지**가 이 로그로 바로 보인다.

`trim-trailer.py` 는 Unity Recorder 녹화본용 보조 도구로 남겨 둔다(암전 구간
자동 판별).  빌드 직접 덤프에는 필요 없다 — 덤프가 본편만 담기 때문이다.
