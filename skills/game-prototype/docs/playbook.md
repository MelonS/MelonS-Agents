# game-prototype playbook — 다음 게임에도 적용되는 침전물

WORKFLOW-V2 규칙 6: 매 사이클 종료 시 "이번에 배운 것 중 다음 게임에도 적용되는 것"을 기록.
스킬의 성공 지표 = 2번째 게임이 같은 품질에 도달하는 속도. (없는 사이클은 "없음"이라고 기록.)

---

## 2026-06-10 사이클 1 — 검증은 운영자 입력 경로에서 (WORKFLOW-V2 탄생)

- API 직접 호출 테스트(V시리즈)만 있으면 "테스트 전부 PASS ↔ 게임은 버그투성이" 괴리가 생긴다.
  클릭→메뉴→명령의 진짜 입력 경로를 시뮬하는 harness(SimInput/ReproHarness)가 전제 조건.
- 증상이 아닌 체인을 잡아라: "벌목 안 됨"의 근본원인은 벌목 코드가 아니라
  수면 decay 과조정 → 수면게이트가 1.5초마다 전 작업 강제해제 → 침대 없어 잠도 실패 → 무한 thrash.
  needs 튜닝 하나가 전 작업 시스템을 마비시킬 수 있다 — **게이트 조건은 "대안이 실제로 실행 가능할 때만"**.

## 2026-06-10 사이클 2 — 재현 시나리오는 코드만큼 디버깅이 필요하다

repro_all 스위트 첫 가동: 6건 중 3건 FAIL — **전부 게임 버그가 아닌 시나리오 결함**이었다.
FAIL ≠ 곧 버그. 시나리오 작성 함정 5종 (모두 오늘 직접 밟음):

1. **자가조절 시스템에 바닥값 assert 금지** — "food ≤ 24.5 까지 굶기기"는 림이 food<40 에서
   알아서 먹으므로 자연경로에서 영원히 안 온다(그게 정상 동작). 바닥값(needBelow) 대신
   **단조 구간의 하락량(needDrops)** 으로: 시작 직후(food/sleep 80)엔 식사·수면붕괴가 불가능해
   하락이 단조 → 결정론. 자가조절을 끄고 싶으면 세팅 가능한 다른 축으로 (배고픔 대신 수면 부족 —
   침대가 없으면 수면은 자가 해소 불가).
2. **세팅→효과 적용 레이스** — setNeed 후 효과(thought 델타)는 다음 시스템 틱(~1s)에 적용된다.
   "하락량" 기준값 probe 를 세팅 **직후**(효과 적용 전)에 두지 않으면 기준값이 하락 후에 찍혀
   드롭 0 으로 측정된다. 순서: setNeed → needDrops(기준값 선점) → hasThought.
3. **임계값은 시스템 기하에서 도출, 어림 금지** — "나무에 도달"의 정상 상한은 stand-cell 모델에서
   대각 인접칸 중심 1.414 + 도착 허용오차 ~0.5 ≈ 1.9. 어림값 1.7 을 썼더니 정상 벌목(1.80/1.94)이
   FAIL 로 측정됐다. 임계값 주석에 도출 근거를 남겨라.
4. **기준값 스냅샷 시점** — "개수 감소" probe 를 긴 관찰 스텝 뒤에 두면 사건(나무 쓰러짐)이
   이미 지나간 뒤 기준값을 찍는다(44→44). 완료 이벤트보다 먼저 기준값을 찍도록 배치.
5. **Destroy=PASS 오탐 가드** — "더미가 사라짐 = 내구도 소진" 판정은 운반/병합으로 인한
   조기 소멸과 구분해야 한다. 마지막 관측값이 거의 0일 때만 소진으로 인정.

추가 침전물:
- **글로벌 시간 상수는 단일 소스로** — "하루 길이"를 파일마다 각자 가정(24초 vs 실측 ~1,000게임초)
  하면 41x 속도 차이 같은 게 조용히 산다. 새 게임은 Day 0 에 GameClock 상수부터 박고 전부 참조.
- **스위트(repro_all)는 커밋 게이트이자 시나리오 디버거** — 시나리오 자체의 결함을 빌드마다 드러내준다.
- 진단 로그에 **행위 주체를 남겨라** (`ClearTask by=PawnChopper.Update` 스택 기록) — 측정 결함과
  진짜 버그를 가르는 데 결정적이었다 (give-up 로그 부재 → destroyed 경로 확정 → 스크린샷 검증).

## 2026-06-10 사이클 3 — longplay 가 잡는 버그의 결 (폭풍 전원 정신붕괴)

- **invariant 0 이어도 타임라인 패턴이 버그를 드러낸다**: "림 3명의 mood 가 같은 스냅샷에서 동시에
  정확히 0" — 동시성 + 동일값 + 클램프 경계값은 전역 이벤트/공유 상태/폭주 페널티 냄새.  스냅샷
  테이블에서 '값이 같아지는 순간'을 의심하라.
- **catalog 에만 있고 미배선 패턴 (2회째)**: 배고픔(99a286a 이전), 야외 폭풍.  데이터(catalog/config)에
  정의된 효과는 **소비처 grep 전수 확인**이 빠른 감사 — `AddThought("X")` 0건이면 dead entry.
- **수치 효과는 단일 모델 경유 강제**: mood 직접 드레인(3f*dt)이 thought 모델을 우회하며 살아 있었다
  → 이중 페널티 + 폭주.  스탯에 영향 주는 모든 코드는 한 경로(여기선 thought)로 수렴시켜야 잔존
  우회로가 밸런스 붕괴를 못 일으킨다.
- **재정합(rescale)은 전수 수색**: #234 가 needs decay 를 새 시계로 축소할 때 폭풍 드레인(3f)과
  WoodPile("24초=1일")은 누락 — 상수 리스케일 작업은 같은 단위를 쓰는 **모든** 곳을 grep 으로
  찾아 한 커밋에서 끝내라 (누락분이 41x/62x 괴물로 잠복).
- **도착 판정은 '영역 진입'이 아니라 '목표점 근접'으로**: 게이트 통과가 이동을 끊는 구조
  (`AtStandCell → ClearTarget`)에서 셀-일치 판정은 "경계 밟는 순간 동결"을 만든다 — 림이 셀
  모서리(목표물에서 2.12)에 얼어붙어 허공 작업.  같은 시나리오 4회 반복 중 1회만 재현(진입 지점이
  모서리일 때만) — **간헐 재현은 경계조건 냄새**, 반복 실행이 잡는다.  수정은 호출부 14곳이 아니라
  판정 함수 1곳에서 (중심 근접 0.3 추가).

## 2026-06-14 — 디자인 폴리싱: 단일반복 타일 디그리딩 + 고정폭 셀 텍스트 오버플로우

- **단일 타일이 대면적 반복될 땐 타일 자체가 저대비·이음매여야 한다.** 바위는 PathGrid 가 타일
  레퍼런스 동일성(`t == _rock`)으로 통행 차단을 판정 → 변형 추가 불가(추가 시 그 셀이 통행
  가능해져 게임플레이 변경).  그래서 `tile32_rock_a` 한 장이 전 바위 셀에 반복(+flip-X 뿐)되는데,
  `rock_tile()` 이 큰 고대비 LT/DK 패치 4개를 셀마다 같은 자리(±2px)에 깔아 명/암 덩어리가 행으로
  정렬 = 다이아몬드 격자("QR 지면", 오버뷰 최대 눈엣가시).  잔디/흙은 작은 2~3px 저대비 클러스터를
  전면 균일 산란 + 1px MD 테두리라 매끈했다 — 같은 규율을 바위에 이식해 해소.
  → **일반 규칙: 반복 타일의 격자 위험은 타일당 휘도 stdev 로 정량화하라.** 잔잔한 기준 타일
  (잔디 5.9·흙 6.2)의 2배(구 바위 14.2)면 격자가 보인다.  신 바위 5.1 → 5×5 반복·a/b+flipX 무격자
  (격리 grader R1 PASS).  변형을 못 늘리는 타일(통행성 키)일수록 더더욱 균일·저대비·이음매가 답.
- **고정폭 셀의 텍스트는 `Overflow` 금지.** ArchitectMenu 제거 버튼 라벨("저장/폐기 영역 제거" 9자)이
  `horizontalOverflow=Overflow` + 68px 셀에서 옆으로 흘러 잔디(월드) 위에 떠버렸다(strip 배경은
  68px뿐이라 글자만 노출).  → 셀엔 축약명("저장 제거")·툴팁엔 전체 설명, + 안전망으로 텍스트를
  `Wrap`+세로 Overflow(아래로 줄바꿈, 옆으로 월드 침범 원천 차단).  새 게임 UI 셀 컴포넌트 기본값은
  Overflow 가 아니라 Wrap 로.  곁들여: 제거/삭제 글리프를 순적색으로 두면 "오류/비활성"으로 읽힌다
  — 차분한 톤(테라코타)으로 "경고 아닌 도구" 신호 (grader R3: ✕ 235,102,89 → 199,133,117 PASS).
- **표현 레이어 폴리싱의 same-layer 증거 = fresh-build 스샷 + 격리 grader.** 픽셀 변화는 repro
  하네스로 fresh-build 후 운영자 시점 스샷을 떠 작업맥락 없는 grader 가 before/after 픽셀 인용으로
  R 항목별 평결.  기능 회귀는 repro_all 게이트가 따로 본다 — 클릭 타깃 불변이면 위험 ≈0 (게이트
  시나리오의 clickui label 목록과 대조: 변경한 erase 셀은 어떤 게이트도 이름으로 안 누른다).

## 2026-06-14 야간 자율 세션 — QA 방법론 + 위키-RAG + 무인 검증 패턴

- **전 패널 ui-tour + 격리 grader 스윕 = 값싼 QA 광맥.** 모든 패널/탭/메뉴를 여는
  캡처 시나리오(ui-tour) 한 번 + 작업맥락 없는 grader 가 각 스샷을 "보이는 결함"
  기준으로 훑으면 '미완성처럼 보이는' 버그가 무더기로 나온다(이번: Pawn(Clone) 행이름·
  제목/본문 겹침·한글UI 속 영문·중복 버튼).  새 게임은 all-panels 캡처 시나리오를 1순위로.
- **GameObject 이름(.name="X(Clone)")이 UI 라벨로 새는 버그 클래스.** 표시는 항상
  DisplayName 프로퍼티로.  `grep '\.text = .*\.name'` / `MakeLabel(.*\.name` 로 전수 점검.
  (이번: WorkTabUI/ScheduleUI 행이 p.name → PawnName 누락, 정렬은 이미 PawnName 썼는데 표시만.)
- **lazy-build 패널의 제목↔본문 겹침.** 제목 rect 가 한 레이아웃(탭 스트립 있음) 기준
  1회 정규화됐는데 다른 모드(엔티티=스트립 숨김)에서 재사용되면, 본문은 가정한 밴드가
  아니라 제목의 *실제* 위치 아래부터 시작해야 한다.
- **위키-RAG: 직접 fetch 403 → WebSearch 스니펫으로 정본 수치 추출.**  비교는 RISK
  오름차순 갭표로, 저위험·검증가능부터 적용.  docs/wiki-ref/*.md 에 정본 노트 영구 보존.
- **무인 검증 가능성은 하네스 op 가 결정한다.**  배치 고르기 전에 op 목록부터 확인:
  setNeed+hasThought 있음 → 허기/무드 thought 효과 검증 가능; setSkill 없음 → 스킬×수율
  효과 검증 불가(보류).  검증 못 하는 밸런스는 무인 적용 금지(운영자 빌드/OK 후).
- **밸런스 임계 변경 전 '작동 구간'부터 분석.**  허기 thought 임계(25→35)는 폰이
  eatThreshold=50 에서 먹어 평시 food>45 → 깊은 티어는 기아 시에만 발화 = 실임팩트/회귀
  둘 다 작다.  값이 실제로 언제 트리거되는지 추론하면 막연한 회귀 공포를 줄이고 안전 적용.
- **효과-판별 어서션: 신/구 동작이 갈리는 입력을 골라라.**  food=30 에서 "배고픔"을
  어서트하면 구코드("출출함")와 신코드("배고픔")가 갈려 회귀와 효과를 한 번에 증명한다.

## 2026-06-14 야간 (이어서) — 회귀 런타임 진단 + 함정 2종

- **이중 렌더러가 "직립 회귀"의 진범 — tint-anchor 루트가 draw-disable 안 됐다.**
  폰은 [root SR(draw-disable, tint 앵커) + 가시 자식 SR(bob/facing/회전/dim)] 구조.
  art-v2 파이프라인(PawnSpriteAnimator) 도입 후 런타임에 루트 SR 이 enabled=true 로
  남아(빌드시 sr.enabled=false 가 프리팹/씬에 미지속) 자식 위에 **직립 몸통을 덧그림**.
  깨어있을 땐 직립끼리 겹쳐 안 보이다가, 수면 78° 회전 시 자식만 돌아 직립 루트가
  노출 = "침대 위 직립" 회귀.  → 일반 규칙: **"앵커는 두되 그리지 않는다" 패턴은 매
  프레임 enabled=false 를 강제하라**(빌드시 1회 설정은 프리팹 재생성/파이프라인 변경에
  유실된다).  소유 컴포넌트(여기 PawnSpriteBob)가 관계를 매 프레임 보증.
- **런타임 진단 사다리(정적으로 안 보일 때)**: 부착(무조건 Update 로그) → 상태/needs/
  child-null → roll 도달값 → 설정직후 z vs LateUpdate z(프레임내 클로버) → **전 렌더러
  열거(name·enabled·z·alpha)**.  마지막 열거 한 방에 "잉여 직립 렌더러"가 잡혔다.
  코드가 다 맞는데 결과가 틀리면 "보이는 것이 내가 생각한 그 객체가 맞나"를 의심하라
  (회전은 적용됐는데 다른 렌더러가 덮고 있었다).
- **함정: 런타임 로그는 LocalLow Player.log 가 아니라 하네스 `-logFile`.** repro_run 은
  `-logFile G:/ai/_repro_run__<scenario>.log` 로 찍는다.  LocalLow/<co>/<product>/
  Player.log 는 stale(다른 실행분)일 수 있어, 그걸 읽으면 정신붕괴/exception 수치까지
  오보한다(이번에 0/7 로 오독 → 실제 1/0).  소크·진단 검증은 반드시 `-logFile` 경로를.
