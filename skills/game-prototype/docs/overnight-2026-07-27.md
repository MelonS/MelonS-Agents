## 작업 방식

- **가상 유저 페르소나 QA**: 실제 배포본 스크린샷을 에이전트가 **직접 열어 보고**
  사람처럼 평가.  라운드마다 다른 직군/성향으로 구성해 같은 눈이 반복되지 않게 함.
- **원인까지 파고들기**: 증상만 고치지 않는다.  예) "베리덤불이 크다" → PPU 32
  강제 → `AssetPostprocessor` 가 범인 → 예외 처리 + 전수 대조 게이트 신설.
- **게이트 실행 중 소스 편집 금지**: 이 규칙을 두 번 어겨 17/17 FAIL 오탐을 만들었다.
  스테일 빌드 가드는 `.cs` mtime 만 보므로, `.cs` 를 건드리면 실행 중인 시나리오가
  전부 빌드 거부된다.  이후로는 편집 → 빌드 → 게이트 순서를 배치로 묶었다.

## 라운드 1 — 페르소나 10인 (면접관·장르유저·비게이머·UX·아트디렉터·인디개발자·
스트리머·QA·캐주얼·해커톤심사위원)

### 만장일치 1순위: "게임이 멈춘 것 같다"

게임 내 8시간 42분(6:00 AM → 2:42 PM)을 6배속으로 돌려도 자원 카운터 5개가
**한 글자도 변하지 않았다.**  그 와중에 튜토리얼은 "이제 콜로니스트가 알아서
일합니다"를 띄운다.

> 면접관: "게임이 자기 자신에 대해 거짓말을 하고 있다.  이게 제일 나쁘다."
> 해커톤 심사위원: "나머지를 다 고쳐도 이거 하나면 떨어진다."

**원인은 버그가 아니라 시작 상태였다.**  이 게임은 시작 목재 300을 물리 더미로
흩뿌린다(장르 정공법 — 운반이 실제 노동이고, 평가자들이 오히려 극찬한 설계).
그런데 **저장구역이 하나도 없어 운반 대상이 없었다.**  결과: 아무도 안 움직임.

**조치**: `GameManager` 가 시작 시 스폰 북동쪽에 3×3 저장구역을 깐다.

| | 시작 | 3배속 30초 후 |
|---|---|---|
| 목재 | 0 (+300 바닥) | **300** |
| 식량 | 0 | **60** |
| 정착지 가치 | 90 | **396** |

이후 식량이 60→57→55 로 줄어드는 것까지 관찰됨 = 콜로니스트가 실제로 먹는다.
(부수 효과: QA 페르소나가 제기한 "허기가 안 줄어든다" 가설이 반증됐다 —
먹을 게 없어서 안 먹은 것이었다.)

### 밝은 글자 × 밝은 패널 — UI가 안 보이던 진짜 이유

UX 페르소나 실측: **UI 텍스트 14곳 중 WCAG 4.5:1 을 넘긴 곳 0곳**, 그중 5곳은
**1.00~1.52:1**(사실상 안 보임).  특히 연구 항목 제목이 **1.00:1** — 배경색과 동일.

원인: UI 팔레트가 어두운 테마 → 크림 테마로 바뀌었는데,
**일부 파일이 어두운 테마 시절의 밝은 글자색을 하드코딩**한 채 남아 있었다.
`UITheme.textPrimary` 는 진갈색(#3A2F22)으로 제대로 바뀌어 있었으므로, 테마를
쓰지 않고 리터럴을 박아둔 곳만 크림 위 크림이 된 것.

- `ResearchUI`: 선택 가능 항목 `#F2E4D0`(크림) → 배경에 녹음.
  평가자들이 "2·3번 연구는 이름이 아예 없다"고 읽은 이유.
- `PawnInfoPanel`: `#dddddd`, `#ddc28a`, `#888888` 등 20곳.
  운영자가 스크린샷으로 물은 "장비 탭이 껍데기만 있는 거지?" 의 정체 —
  껍데기가 아니라 **내용이 보이지 않는 색으로 그려지고 있었다.**

**조치**: 두 파일의 색 리터럴을 크림 패널용 어두운 값으로 교체.
(밝은 리터럴을 쓰는 파일은 전체에서 이 2개뿐임을 grep 으로 확인.)

### 주간 채도

아트 디렉터 페르소나가 픽셀 실측으로 지적: 잔디 H68 S58 V64 / 모래 H46 S58 V93 —
색상각 차이가 22°인데 채도가 같아 화면이 산성 라임톤.  반면 새벽 스톱은 호평.
`ColorGradeDriver` 의 한낮/오후 스톱이 채도를 **1.10 부스트**하고 있었다(새벽은 0.90).

**조치**: 0.94 로 하향 + 대비 1.05→1.03.  잔디 채도 실측 S68 → **S57**.
스프라이트는 한 장도 새로 그리지 않음.

## 시나리오 2건 갱신 — "버그를 고쳤더니 빨간불이 된" 사례

- `p1-wood-durability`: 임계값이 A1 수정 **이전의 버그 스케일**(dt/24)에 맞춰져 있어,
  정합(dt/1000) 이후 영원히 만족 불가였다.  기대값이 옛 버그를 박제한 것.
- `p0-pawn-move`: 콜로니가 바빠지며 폰이 흩어져 목표까지 거리가 매번 달라졌다.
  실측 2회 연속 실행에서 0.3초 통과 / 12초 실패로 갈렸다.  판정 기준(0.8)은 그대로 두고
  시간 창만 25초로.
