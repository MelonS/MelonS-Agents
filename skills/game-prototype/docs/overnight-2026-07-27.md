## 라운드 1 — 페르소나 10인 (면접관·장르유저·비게이머·UX·아트디렉터·인디개발자·

### 만장일치 1순위: "게임이 멈춘 것 같다"

게임 내 8시간 42분(6:00 AM → 2:42 PM)을 6배속으로 돌려도 자원 카운터 5개가
**한 글자도 변하지 않았다.**  그 와중에 튜토리얼은 "이제 콜로니스트가 알아서
일합니다"를 띄운다.

> 면접관: "게임이 자기 자신에 대해 거짓말을 하고 있다.  이게 제일 나쁘다."
> 해커톤 심사위원: "나머지를 다 고쳐도 이거 하나면 떨어진다."

**원인은 버그가 아니라 시작 상태였다.**  이 게임은 시작 목재 300을 물리 더미로
흩뿌린다(장르 정공법 — 운반이 실제 노동이고, 평가자들이 오히려 극찬한 설계).
그런데 **저장구역이 하나도 없어 운반 대상이 없었다.**  결과: 아무도 안 움직임.

**조치**: `GameManager` 가 시작 시 스폰 북동쪽에 3×3 저장구역을 깐다.

| | 시작 | 3배속 30초 후 |
|---|---|---|
| 목재 | 0 (+300 바닥) | **300** |
| 식량 | 0 | **60** |
| 정착지 가치 | 90 | **396** |

이후 식량이 60→57→55 로 줄어드는 것까지 관찰됨 = 콜로니스트가 실제로 먹는다.
(부수 효과: QA 페르소나가 제기한 "허기가 안 줄어든다" 가설이 반증됐다 —
먹을 게 없어서 안 먹은 것이었다.)

### 밝은 글자 × 밝은 패널 — UI가 안 보이던 진짜 이유

UX 페르소나 실측: **UI 텍스트 14곳 중 WCAG 4.5:1 을 넘긴 곳 0곳**, 그중 5곳은
**1.00~1.52:1**(사실상 안 보임).  특히 연구 항목 제목이 **1.00:1** — 배경색과 동일.

원인: UI 팔레트가 어두운 테마 → 크림 테마로 바뀌었는데,
**일부 파일이 어두운 테마 시절의 밝은 글자색을 하드코딩**한 채 남아 있었다.
`UITheme.textPrimary` 는 진갈색(#3A2F22)으로 제대로 바뀌어 있었으므로, 테마를
쓰지 않고 리터럴을 박아둔 곳만 크림 위 크림이 된 것.

- `ResearchUI`: 선택 가능 항목 `#F2E4D0`(크림) → 배경에 녹음.
  평가자들이 "2·3번 연구는 이름이 아예 없다"고 읽은 이유.
- `PawnInfoPanel`: `#dddddd`, `#ddc28a`, `#888888` 등 20곳.
  운영자가 스크린샷으로 물은 "장비 탭이 껍데기만 있는 거지?" 의 정체 —
  껍데기가 아니라 **내용이 보이지 않는 색으로 그려지고 있었다.**

**조치**: 두 파일의 색 리터럴을 크림 패널용 어두운 값으로 교체.
(밝은 리터럴을 쓰는 파일은 전체에서 이 2개뿐임을 grep 으로 확인.)

### 주간 채도

아트 디렉터 페르소나가 픽셀 실측으로 지적: 잔디 H68 S58 V64 / 모래 H46 S58 V93 —
색상각 차이가 22°인데 채도가 같아 화면이 산성 라임톤.  반면 새벽 스톱은 호평.
`ColorGradeDriver` 의 한낮/오후 스톱이 채도를 **1.10 부스트**하고 있었다(새벽은 0.90).

**조치**: 0.94 로 하향 + 대비 1.05→1.03.  잔디 채도 실측 S68 → **S57**.

## 라운드 2 — 페르소나 5인 (접근성·시니어프로그래머·11세·사운드디자이너·프로듀서)

라운드 1과 겹치지 않는 시각으로 재구성.  이 라운드는 **실측 도구를 쓰게** 지시해서
"느낌"이 아니라 숫자가 나왔다.

### 접근성 — UI 텍스트 45곳 중 WCAG AA 통과 **3곳**

관측색을 `fg = α·잉크 + (1-α)·배경` 으로 역산하니 **α ≈ 0.29 로 채널 편차가 거의 없었다.**
= 작은 글리프(실측 7~11px, 단축키는 3~4px)에서 안티에일리어싱이 획을 먹고 있다는 서명.

글자 크기를 키우면 레이아웃 파급이 커서 야간에 위험하므로, **잉크를 진하게** 하는 쪽으로
갔다 (같은 α 라도 대비가 오른다).  페르소나가 크림 배경 기준 4.5:1 통과선을 계산해 줘서
그 값을 `UITheme` 크림 팔레트에 반영:

| 항목 | 전 | 후 | 대비 |
|---|---|---|---|
| textSecondary | (138,118,88) | (102,93,79) | 2.6 → 4.6:1 |
| accentGold (헤더) | (158,113,33) | (128,88,24) | 3.0 → 4.6:1 |
| accentOrange (활성 버튼 배경) | (196,122,44) | (145,90,33) | 2.7 → 4.5:1 |

색상(hue)은 유지하고 명도만 내려 팔레트 아이덴티티는 그대로다.

**색-전용 정보**도 실측됐다: 녹색맹 시뮬에서 일정표의 작업(초록)↔여가(갈색) 색차가
ΔE 38.9 → **20.2**, 적색맹에서 **12.1** (10 미만이면 구분 불가).  72칸이 순수 색 블록이라
색이 무너지면 정보가 0이 된다.  → **셀마다 1글자(자/수/작/여) 추가.**

### 사운드 — 제 BGM 작업의 결함을 잡았다

교체한 BGM 이 **57초마다 4.75초간 사라지고** 있었다.  ElevenLabs 출력의 페이드인(약 4초)·
아웃(2초)을 안 잘라낸 채 루프로 만들어서다.  3분 시연이면 3번 발생.
→ 페이드 구간 트리밍 후 재루프.  바디 대비 -6dB 이하 구간 **4.75s → 2.00s**.

같이 나온 것 (이번 회차 미처리, 아래 "안 고친 것" 참조): `danger.wav` 가 에너지의 82%가
60Hz 아래라 **노트북 스피커에서 레이드 음악이 −29.9dB 사라진다.**

### 프로듀서 — 내가 만든 검증 도구의 오탐을 걸러낸 사례

프로듀서 페르소나가 "건축 서브메뉴가 안 열린다"를 **1순위 진범**으로 지목하고 85분을
배정했다.  그런데 `p2-first10min` 시나리오는 건축→구조→목재벽→배치를 실제로 통과한다.
확인해 보니 **내가 건축 패널을 위로 옮긴 뒤 증거 캡처 스크립트의 좌표가 낡아** 엉뚱한 곳을
클릭하고 있었다.  기능은 멀쩡했다.

> 교훈: 페르소나 리포트도 **증거이지 결론이 아니다.**  특히 "안 열린다/안 된다"류는
> 내 캡처 도구의 상태를 먼저 의심해야 한다.  이걸 확인 안 했으면 없는 버그에 85분을 썼다.

### 시니어 프로그래머 — 튜토리얼이 건너뛰어지는 이유

"시작 직후 일시정지 상태인데 이미 ②번 힌트가 떠 있다"를 지적.
원인은 **내 시작 저장구역 변경의 부작용**이었다: ① 단계의 통과 조건이
"StockpileZoneEntity 가 1개 이상"인데 시작 저장구역이 그걸 즉시 충족시킨다.

빈 단계를 남기는 대신 **생산이 멈추는 진짜 원인을 가르치는 단계**로 교체:
① = "나무 우클릭 → 벌목" (Gate.Chop 신설).  초기 목재 300 이 창고로 들어간 뒤에는
새 일감이 없어 콜로니가 멈추는데, 그걸 푸는 첫 행동이 벌목 지정이기 때문이다.

### 그 밖에 처리한 것

- **튜토리얼 판독성**: 같은 단계가 25초 지나면 알파 **0.35** 로 딤되고 있었다.
  초보자는 한 단계에 25초를 쉽게 넘기므로 **안내가 대부분의 시간 읽을 수 없는 상태**였다.
  (11세 페르소나: "글씨가 반투명이라 뒤에 나무가 비쳐요. 읽다가 포기했어요")
  → 40초 후 0.80 으로. 가림보다 판독성 우선.
- **튜토리얼 거짓말 문구**: "이제 콜로니스트가 알아서 일합니다" → "이제 일감을 지정해
  보세요. 나무를 우클릭 = 벌목".  아무도 일하지 않는 화면에서 저 문장이 뜨는 게
  라운드 1·2 통틀어 가장 반복적으로 지적됐다.
- **연구 패널 4번 항목 잘림** → 내용 높이를 따라가게 (`FitPickerToText`).
- **빈 스킬 상자** → 씬이 구워질 당시의 밝은 글자색이 크림 패널에서 안 보였던 것.

## 라운드 3 — 검증 라운드에서 잡은 것: **"고쳤다고 착각할 뻔한 수정"**

수정 전(r2)/후(r3) 스크린샷을 **같은 파일명끼리 나란히 놓고** 비교한 결과,
튜토리얼 문구가 **전혀 바뀌지 않았다.**  화면에는 여전히
"좋습니다! 이제 콜로니스트가 알아서 일합니다."가 떠 있었다.

### 원인 — Unity 직렬화 함정

`TutorialOverlay.tips` 는 `public Tip[] tips = new Tip[]{...}` 형태의 **public 필드**다.
Unity 는 public 필드를 **씬에 직렬화**하고, 씬에서 컴포넌트를 로드할 때 **저장된 값으로
코드의 초기화식을 덮어쓴다.**  따라서:

- 문구 수정 → 무효
- `Gate.Chop` 신설 + ① 단계 교체 → 무효
- (알파/딤 수정은 `Update()` 안의 코드라 **유효** — 그래서 일부만 반영돼 더 헷갈렸다)

`[System.NonSerialized]` 를 붙여 직렬화를 끊고 **코드를 단일 정본**으로 만들었다.
씬 리베이크(Game.unity 전체 재작성)는 야간에 하기엔 위험 대비 이득이 없다.

### 왜 이게 오늘 밤 가장 중요한 교훈인가

이 수정들은 **컴파일도 통과하고, 게이트 17/17 도 통과하고, 배포도 성공**했다.
"고쳤다"고 보고할 조건을 전부 만족했는데 화면은 그대로였다.
`ColorGradeDriver.STOPS` 와 `UITheme.Pals` 는 `private static readonly` 라 같은 함정에
걸리지 않았고(채도 실측 S68→S57 로 반영 확인), 그래서 **일부는 반영되고 일부는 안 되는**
상태가 만들어져 육안으로도 놓치기 쉬웠다.

> 규칙: **UI/데이터 값을 고쳤으면 수정 전/후 스크린샷을 나란히 놓고 확인한다.**
> 빌드 성공·게이트 통과는 "화면이 바뀌었다"의 증거가 아니다.
> (같은 계열의 교훈이 오늘만 세 번 나왔다 — GUID 소실, gitignore 결손, 이번 직렬화)

### 검증 라운드가 잡아낸 내 회귀

`Gate` enum 에 `Chop` 을 **중간에 삽입**해서 씬에 저장된 게이트 번호가 한 칸씩 밀렸다
(2/3/4 = House/Farm/Done → Chop/House/Farm).  "②집" 팁이 *벌목했는가*로,
"③농장" 팁이 *벽을 세웠는가*로 판정되는 상태.
`[NonSerialized]` 로 씬 값을 무시하게 되면서 이 회귀도 함께 해소됐다.

> enum 에 값을 **중간 삽입**하면 직렬화된 정수가 전부 밀린다.  append-only 계약이
> 이 프로젝트에 이미 있었는데(`Mode enum append-only`, RESUME 문서) 다른 enum 에서
> 같은 실수를 했다.
