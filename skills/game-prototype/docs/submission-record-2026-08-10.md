PDF 두 종은 원본 마크다운이 커밋돼 있으므로 언제든 재생성된다.


```
                      재배포 금지.  워크트리를 지워도 origin 에 남으므로 안전.
```

**게임 코드를 고쳐도 심사자가 보는 것은 배포된 빌드다.**  지금부터의 게임 작업은
전부 본선용이라는 뜻이다.

## 시연 영상은 네 판을 찍었다

폐기한 세 판은 `art-out/아카이브_NAN2026/영상이력/` 에 있었다.  파일 자체는 다시
만들 수 없지만(그때의 코드 상태가 다르다) **왜 폐기했는지가 자산**이므로 여기 남긴다.

| 판 | 폐기 사유 |
|---|---|
| 1차 | 배율 `ortho 14` 로 찍어 주민 활동 라벨이 해상도 아래로 사라졌다.  55초가 사실상 1샷이고 게임에 있는 위협이 하나도 안 나온다.  운영자 평가: *"머하는 게임인지도 모르겠고 쓰레기 영상 같음"* |
| 2차 | Unity Recorder(에디터 배치모드)로 찍었더니 게임이 **빌드와 다른 상태**로 돌았다 — 침대 3개(빌드 6개), 목재 270(빌드 1,600).  uGUI 텍스트가 프레임에서 통째로 빠져 자원·목표·토스트가 빈 박스로 나왔다 |
| 3차 | 화면은 멀쩡해 보이지만 **주민에게 전투 행동이 없던** 시절.  적이 마을에 들어와도 주민은 하던 일을 계속했고 적이 혼자 걸어와 혼자 쓰러졌다 |
| 4차 | 제출본 |

### 세 판을 버리며 배운 것

매번 "촬영 문제"로 보였고 매번 아니었다.

- 1차 → 배율·구도 문제로 보였다.  실제로는 **찍을 사건이 없었다.**
- 2차 → 촬영 도구 문제였다.  녹화 경로가 게임을 다르게 돌린다.
- 3차 → 카메라가 전투를 못 잡는 문제로 보였다.  실제로는 **게임에 전투 행동이
  없었다.**  카메라를 다섯 번 조정하는 동안 게임 코드는 한 번도 열지 않았다.

> 화면에 무엇이 없는지가 아니라 **게임이 무엇을 하지 않는지**를 물어야 한다.

자세한 기록: [`trailer-production.md`](trailer-production.md) §8,
[`known-limitations.md`](known-limitations.md).

## 마감일 하루에 고친 것

전부 운영자가 완성본을 보고 지적한 것들이고, 전부 **화면만 보고 게임 코드를 열지
않아** 놓쳤던 것들이다.

| 지적 | 진짜 원인 |
|---|---|
| "적이 자기 혼자 픽하고 죽는다" | 주민에게 **전투 행동 자체가 없었다.**  행동 목록 20종에 전투가 없어 적을 무시하고 하던 일을 계속했다 |
| "너무 빨리 죽는다" | 전투를 고치자 넷이 붙어 1.25초에 죽었다 → 약탈자 HP 20→48 (공격력은 그대로) |
| "자동 게임 같다" | 자막 8개 중 5개의 주어가 '주민'이었다.  플레이어가 무엇을 하는지 한 문장도 없었다 |
| "UI 인터페이스가 안 나온다" | 조작 수단(하단 버튼 바·초상화 바)을 껐던 것이 잘못.  지우면 화면이 저절로 굴러가 보인다 |
| "실제 버튼을 누르는 행위를 보여줘야" | 커서가 좌표로 이동해 파문만 그리고 UI 는 코드가 따로 열었다 → 버튼을 라벨로 찾아 `onClick` 을 실제 호출 |
| "추가 지은 벽들이 무쓸모" | 벽 5칸을 한 줄로 세웠다.  방을 닫지 못하니 지붕도 안 생긴다 → 6×5 방 + 문 + 침대 2 + 등잔.  '지붕 아래 잠자리' 6/9 → 8/9 |
| "1초에 자고 있는 장면" | 워밍업이 새벽에 끝나 페이드인이 새벽 마을을 드러냈다 → 첫 컷 상태를 촬영 시작 전에 만든다 |

회귀 방지로 `repro-scenarios/p2-defend-raid.json` 을 게이트에 넣었다.  이 시나리오는
1차 실행에서 실패했고(`activity='산딸기 운반'`), 그 실패가 두 번째 원인인
busy-gate 를 찾아냈다.  화면만 봤다면 "여전히 안 되네"에서 멈췄을 것이다.
